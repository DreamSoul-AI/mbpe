## 主对照

每行对应同一批 32 张测试图，三个方法的数字顺序是「自动 / 固定 / 二维」。64、256 为每套词表的规则数，自适应文件含两套，合计分别为 128、512 条。固定和二维各一套。实际字节为文件长度，包含词表、适用的码表、方向位、二维位移、文件头、块头和填充。

| 布局 | 每套规则 | 后端 | 固定扫描 | token 数 | 文件字节 |
| --- | ---: | --- | --- | ---: | ---: |
| 紧凑块 | 64 | Huffman | 按列 | 44,247 / 44,247 / 14,765 | 30,515 / 30,331 / 10,150 |
| 紧凑块 | 64 | zlib | 按列 | 44,247 / 44,247 / 14,765 | 33,375 / 33,259 / 13,795 |
| 紧凑块 | 256 | Huffman | 按列 | 33,491 / 33,491 / 10,097 | 31,534 / 30,694 / 10,472 |
| 紧凑块 | 256 | zlib | 按列 | 33,491 / 33,491 / 10,097 | 36,515 / 35,935 / 13,082 |
| 混合长条 | 64 | Huffman | 按列 | 19,181 / 96,644 / 21,699 | 16,683 / 67,307 / 13,621 |
| 混合长条 | 64 | zlib | 按行 | 19,181 / 96,660 / 21,699 | 16,773 / 32,803 / 19,396 |
| 混合长条 | 256 | Huffman | 按行 | 13,400 / 71,336 / 11,169 | 15,393 / 65,999 / 11,809 |
| 混合长条 | 256 | zlib | 按行 | 13,400 / 71,336 / 11,169 | 16,865 / 33,268 / 14,290 |

每个自适应文件的文件头和 32 个块头合计 270 字节。32 个方向位占 4 字节，解码器按方向位选扫描、词表和码表。两套词表在 64、256 条下共占 224、1,152 字节，两张 Huffman 码表另占 136、520 字节。紧凑块全选按列，数据块和固定按列完全等长，新增的 116–840 字节来自额外词表、方向位和适用的码表。

长条 64 条时，Huffman 的平均有效码长为自动 6.69、二维 4.80 比特/token。自动文件多出的 3,062 字节中，3,006 来自数据块，56 来自其余开销。256 条时，分别多 3,256 和 328 字节。

以自动减二维计，混合长条 Huffman 的字节差及配对重采样 95% 区间为 +3,062 [2,622, 3,485] 和 +3,584 [3,164, 4,010]，zlib 为 −2,623 [−3,068, −2,169] 和 +2,575 [2,028, 3,136]。每组按图重采样 10,000 次，种子 37004，每次计一次固定开销。区间描述这批测试图的波动。

## 总规则数相同的补充对照

在主对照完成后，把两个方向的原词表各截为 32 或 128 条前缀，保持冻结阈值，在同一验证集生成新码表。下表为合计 64 或 256 条的自适应文件，固定扫描和二维仍用上表结果。每份文件仍计 4 字节方向位及 270 字节头部，两套词表共 96 或 512 字节，两张 Huffman 码表共 72 或 264 字节。

| 布局 | 合计规则 | 自适应 token | 自适应 Huffman 字节 | 自适应 zlib 字节 |
| --- | ---: | ---: | ---: | ---: |
| 紧凑块 | 64 | 55,211 | 30,803 | 30,076 |
| 紧凑块 | 256 | 37,180 | 30,385 | 11,721 |
| 混合长条 | 64 | 27,240 | 18,308 | 14,240 |
| 混合长条 | 256 | 16,083 | 15,986 | 10,563 |

zlib 前的 token 定宽打包从 7、9 位降至 6、8 位。另取补充对照的原 token，在内存中用多一位打包并按原 zlib 配置重压缩，只测数据块。长条 64 档多 3,686 字节，仍低于二维。256 档紧凑块与长条分别多 28,956 和 7,214 字节，均超过原本相对二维的节省。这个检查隔离了打包宽度的影响，结果记录在 `zlib-width-check.json`。
