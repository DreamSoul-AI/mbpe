# RGB 学习覆盖与词表规模 CPU 对照

## 输入与执行

H2 复用此前原始 RGB 词表和测试，普通 BPE 逐图长度与旧回执一致。H3 复用 E1 的 1000 学习图，另取嵌套 300、3000 图，并新留测试。三个追加种子重新抽取嵌套 1000、3000 学习图，使用同一 H3。H4 从主对照 3000 图扩到 6000 图，测试再留一批，每集 500 张且每类 50 张。两组 H4 追加种子固定 3000 图起点，重新抽扩充的 3000 张。差分与颜色对照复用主 H4 的学习和测试输入。

先核对源文件和像素哈希，排除已知旧池索引及重复内容，冻结候选词表后评估。使用 tokenizers 0.22.2 的 CPU BPE，min_frequency=1，256 个原子，逐通道切分。默认按列，另作按行与 Hilbert 对照。每个预算保存实际规则前缀。最短切分与普通 BPE 共用词条到 ID 的映射。独立进程只读字典、ID 流和身份清单，按每通道展开 1024 值定位，恢复原 RGB 并核对哈希。

## 本机原件

H5 组批核算使用相同的 1000 个固定随机到达顺序、batch=16，并比较 FIFO 和窗口 128 的长度排序。在 FIFO 中，最短切分相对普通合并的累计位置少 12.68%/12.53%，最大单批位置少 10.99%/11.06%（CIFAR-10/SVHN）。在窗口 128 中，累计少 13.05%/13.29%，最大单批少 11.25%/11.21%。这是逐批最大长度乘批大小的静态核算。BF16 输入为每位置 384 字节，bool mask 每补齐位置 1 字节，int32 长度每图 4 字节。结果和分位数见 batch-accounting.json。

输出根位于 tmp/2026-11-17-raw-coverage/。run.py、replicate.py、extend.py、extend_replicas.py、transforms.py、scans.py 和 confirm_scan.py 记录批次入口。各阶段 stages.json 保存实际命令、PID、耗时和退出码。原件包括输入清单、源码和协议快照、封存字典、逐图长度、独立解码回执、parser-audit.json、vocab-use.json 和 integrity-audit.json。analysis.json 保留 H2/H3 完整配对结果。H5 结果及事前选择保存在 scan-confirmation 下。数据和载荷位于 Git 忽略的本机目录。
