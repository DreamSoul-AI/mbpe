# 第 40 批任意形状文件与线性对照

2026-11-14 00:02（Asia/Shanghai）。实际运行 27.01 秒，峰值工作集约 187 MiB。Python 3.13.9、NumPy 2.5.4、zlib 1.3.1。实验和独立解码均为 Idle，绑定一个逻辑 CPU，数据 worker 为零。

## 输入和选择

从第 38 批冻结的 CIFAR-10 索引，按每类前 4、2、4 张抽取 40 张学习、20 张验证、40 张测试。每张图生成 24×32 绿通道裁块、同裁块挖去两个 6×8 内孔后的带孔格子、16×24×3 RGB 格子。原始整数保持不变，三种布局来自同一批源索引。另有五个小格子覆盖标量、空标量、零边长、全空有效域和未见的大整数。

每个布局按 0、64、256 条比较几何 BPE 与固定线性扫描。后者在按行、按列和蛇形中按验证集的完整字节选定。学习集确定词表，验证集确定 Huffman 码表。配置保存后才编码测试格子。zlib 额外将零规则写成与非零规则一致的 9 位。逐图配对重采样 10,000 次，种子 40004。 [事前方案](<../研究记录 Research Record/计划存档 Plan Archive/2026-11-13 第38至40批 CPU 阶段方案.md>) · [输入来源](<2026-11-13 第38批 原始像素完整文件对照.md>)

沿用第 38 批的环境变量，从仓库根执行。

```powershell

```

## 实际文件

表内数字顺序为线性 / 几何。矩形、带孔和三维 RGB 分别有 30,720、26,880、46,080 个测试格点。文件含整数值表、词表、码表、外框和有效域等全部开销。两种方法均达到实际规则预算。

| 矩形 | 64 | 29,712 / 29,738 | 31,486 / 31,587 | 34,892 / 35,048 |

带孔 64 条的 zlib 线性文件选择按行，剩 26,057 个 token。三维 RGB 64 条的 zlib 线性文件选择按列，剩 45,381 个 token。各布局零规则的统一 9 位 zlib 文件为 35,110、34,796、52,553 字节，两种方法相同。

带孔有效域用位图，每张 96 字节，两种方法各计 3,840 字节。稠密外框由各轴边长确定，矩形和三维每组形状字段共 80 和 120 字节。256 条时，矩形和带孔的几何位移各 512 字节，三维 768 字节。三维 256 条的 Huffman 数据块比线性少 135 字节，加上位移后净多 633 字节。zlib 数据块少 341 字节，完整文件净多 427 字节。三维 256 条的几何减线性 token 差为 −329，配对区间 [−591, −87]。三维 64 条的 Huffman 文件差 +127 字节，区间 [−18, 234]。
