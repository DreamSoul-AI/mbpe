## 冻结输入和执行

从第 33 批落盘文件读取词表、顺序及逐图 token，校验文件哈希、计费和样本清单。沿用 16 张验证、32 张测试和原有掩码。四级比较二维 256 与 Hilbert 256。二值先比较上批选定的二维 64 与 Hilbert 256，再补两边均为 64 条的对照。补测的 Hilbert 64 从已存的零规则流应用原词表前 64 条。在验证集逐项匹配已保存的 token 后，才按同一顺序生成测试流。 [第 33 批输入和设置](<2026-11-13 第33批 CelebA完整文件对照.md>)

每套词表用其验证流统计符号频次，所有合法符号加一平滑，再生成规范 Huffman 码长。按符号编号写一字节码长，共享一次。每张的码流独立补齐到整字节，块头记录 token 数与有效位数。共享文件头、词表引用与几何位移沿用原布局。对照端使用第 33 批定宽打包加逐图 zlib 9 的实际文件，新补的 Hilbert 64 也用同一写入方式。源文件与码表在测试中冻结。 [实验入口](../../studies/batch34_token_coding.py)

区间按源文件配对重采样 10,000 次，种子 20261113，固定开销每次计一次。以 Huffman 总差减 zlib 总差，三组变化依次为 −322、−1,307、−988 字节，区间依次为 [−485, −164]、[−1,427, −1,189]、[−1,118, −859]。同一批样本的差距有缩小，三组均未达到计划预设的减半或变号。

按 Hilbert 的实际平均码长计算等预算差距，四级二维多出的 6,118 个 token 对应约 45,792 个有效比特，平均码长差另增加约 3,370 比特。二值等预算多出的 7,835 个 token 对应约 45,279 比特，二维略短的平均码长抵消约 501 比特。该分解描述固定输出的字节差，合并规则为何产生更多 token 仍待验证。
