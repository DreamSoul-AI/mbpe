# 第 35 批紧凑块与长条对照

2026-11-13 22:58–23:02（Asia/Shanghai）。基于本地工作区 `2e93307`，完成 26 份独立文件的逐图还原。

## 输入与配对

每张图是 128×128 四级格子。内部为 7×7 个 16×16 区块，外围填 0。每个区块随机排列 16 个标签，四个值各出现四次。紧凑图将标签铺成 4×4 小块，长条图按标签顺序铺成 1×16。每对共享标签、0–16 格的整体偏移及转置。各集合一半转置，使横条与竖条数量相同。

每图 0、1、2、3 分别出现 6,976、3,136、3,136、3,136 次。每个标签的面积均为 16 格。学习、验证、测试为 24、16、32 对，使用独立种子 35001、35002、35003。清单保存每对的标签、偏移、方向和图像 SHA-256。生成后逐格核对了两种铺法，共 144 张格子，无完全重复。 [事前方案](<../研究记录 Research Record/计划存档 Plan Archive/2026-11-13 第35批 紧凑块与长条对照方案.md>)

## 方法与执行

每种布局分别学习二维频次版和 Hilbert BPE，比较相同的 0、64、256 条前缀。256 条为主对照，64 条用于检查预算敏感性。两种文件后端对同一份 token 分别使用规范 Huffman 和定宽打包加逐图 zlib level 9。Huffman 码表以验证流频次加一构造，按符号编号写入码长。全部比较使用实际总文件字节，计入共享词表、几何位移、码表、逐图块头和填充。按行打包 zlib、二维零规则和 Hilbert 零规则是基线。

按行打包 zlib 基线与二维零规则同大小，紧凑块 15,840 字节，长条 13,542 字节。固定使用 zlib 时，二维 256 条在紧凑块上比该基线少 2,758 字节，在长条上多 748 字节。固定使用 Huffman 时，紧凑块从 64 条增加到 256 条，二维少 4,668 个 token，数据块少 718 字节，词表引用、位移与码表合计增加 1,040 字节，总文件反增 322 字节。

各方法的共享文件头和逐图块头共 270 字节。同预算下，规则引用和 Huffman 码表占用相同。二维的额外位移为 64 条时 128 字节、256 条时 512 字节。其余差距来自数据块。二维测试实际替换中的紧凑块占比，紧凑布局为 48.0%（64 条）、48.4%（256 条），长条布局为 10.9%、12.5%。

## 配对差与判读

两种布局分别计算二维减 Hilbert。交互差为紧凑布局差减长条布局差。负交互差表示紧凑布局扩大二维的相对优势。下表区间为固定词表的源图配对重采样 95% 区间，四舍五入到整数。

| 规则数 | 指标 | 紧凑布局差 | 长条布局差 | 交互差及区间 |
| ---: | --- | ---: | ---: | --- |
| 64 | token | −64,111 | −89,358 | +25,247 [19,851, 30,936] |
| 64 | Huffman 字节 | −46,528 | −69,014 | +22,486 [18,435, 26,688] |
| 64 | zlib 字节 | −51,055 | −75,121 | +24,066 [19,509, 28,860] |
| 256 | token | −47,376 | −64,382 | +17,006 [12,722, 21,595] |
| 256 | Huffman 字节 | −43,507 | −60,310 | +16,803 [13,116, 20,679] |
| 256 | zlib 字节 | −49,663 | −69,525 | +19,862 [15,397, 24,659] |

两种布局、两档非零预算下，32 张各自的 token 差都为负。预设的主检验是 256 条规则的 token 交互差，区间全为正，方向与假设相反。按是否转置分组后，两组的平均 token 交互差仍均为正。

零规则时，zlib 已出现 20,315 字节的交互差。作为事后诊断，扣除每个配对的零规则差后，256 条时 zlib 的交互差为 −453 字节，区间 [−3,019, 2,221]。这一口径下，压缩文件差无法独立归因给合并。Huffman 的零规则两种扫描同长，非零规则下的交互差仍为正。
