## P21 真实 MNIST

真实 28×28 上，二维在两个掩码、两档学习张数、三个预算里都没有短过 Hilbert，也没有短过当时最短的一维。token 和合计比特两项都没有赢。差距随预算变小，但没有跨过去。

最短的一维不总是 Hilbert。1024 条时按行最短。64 条时，bin128 学习 300 张是 Hilbert 最短，学习 1000 张是按列略短于按行；4level 两档都是按列最短。蛇形在这组 MNIST 上没有当过最短。

和 Hilbert 比，学习 1000 张、1024 条时，bin128 二维是 3.8813%（30429），Hilbert 是 3.2554%（25522），二维多 4907 个 token，大约多 19%。4level 二维是 5.6656%（44418），Hilbert 是 5.2700%（41317），大约多 7.5%。同一档按行更短：bin128 2.6818%（21025），4level 4.7778%（37458）。二维比按行分别多大约 45% 和 19% 的 token。

合计比特也没有反过来。二维每一格都高于同预算的 Hilbert，也高于按行。bin128 的按位打包 zlib 是 0.2836 比特/格。这一掩码上最低的 BPE 是按行、学习 1000 张、1024 条，0.2953，仍高于打包 zlib。二维最低是学习 1000 张、256 条的 0.3997，1024 条因为字典更大升到 0.4097。按行在 256 条和 1024 条低于按字节 zlib（0.3128），Hilbert 和二维都没有低于它。

4level 的按位打包 zlib 是 0.5031，按字节是 0.5445。按行从 256 条起低于打包 zlib：学习 1000 张时 256 条 0.5015、1024 条 0.4884。按列在 256 条和 1024 条也低于打包 zlib。Hilbert 最低是 0.5109，没有低于打包 zlib。二维最低是 0.5654，连按字节 zlib 都没有低于。

一阶估计更低，那只是 token 流自己的条件熵。二维的一阶估计仍然高于按行和 Hilbert。前面只读统计里二维上下文比最好一维少大约三成比特，没有变成这次 BPE 的 token 或合计比特优势。

官方学习 254 秒，写出 64 条。学习侧 6853 个 token，100 张里 88 张还原失败。测试套用 103 秒，64 条都套上了（`rules_missed` 为 0），6679 个 token，100 张里 84 张还原失败。`summary.json` 里的比例是用 1024 当每张图的格子数除的，那是 32×32 脚本留下的分母。按 28×28 的 784 格，学习侧是 8.7411%，测试侧是 8.5191%。这两边的 token 数都不是无损长度。

## P23 规则形状

形状按规则展开后的点集算。外接框有一边是 1，算 1×k 长条。两边都至少是 2，并且点数不少于外接框一半，算紧凑块。其余算其他。替换次数是编码重放里真正替换成功的次数，按那条规则的形状归类。这些次数加起来等于格子数减去最后剩下的 token 数。

大块在 64 条时就已经出现，不是要等到 1024。学习 1000 张、bin128、64 条：长条 31、紧凑块 33、面积至少 16 的有 17 条，面积中位数 8，最大面积 224，最长边 28。1024 条时紧凑块占字典的大多数：长条 202、紧凑块 779、其他 43，面积至少 16 的有 517 条，中位数 16，最大面积 536。4level、1024 条是长条 408、紧凑块 593、其他 23，中位数 8，最大面积 400。学习 300 张的字典也是这个趋势，64 条时最大面积已经到 128 或 224。

测试上真正发生的替换仍以长条为主。学习 1000 张、1024 条、bin128：长条替换 599054 次，紧凑块 153617 次，其他 900 次。紧凑块约占全部替换的 20%，尽管它占了 76% 的规则。4level 同一档是长条 593663、紧凑块 145210、其他 709，紧凑块约占 20%。所以块熵里“面积 8 到 16 的方块更常整块同色”这件事，在字典里看得到，但这些大块没有成为测试压缩的主要步骤，token 长度也没有因此短过一维。

方向随学习张数变。学习 300 张、64 条时，bin128 和 4level 的成功替换都以横向为多（大约 51.5 万对 18.7 万）。学习 1000 张、64 条时反过来，以纵向为多（bin128 大约 60.9 万对 11.8 万）。1024 条、学习 1000 张时仍然是纵向替换多：bin128 纵向规则 415 条、横向 317 条、其他 292 条，成功替换 621586、126866、5119。两种方向下，二维都没有短过按行或 Hilbert。

## P24 放大到 56×56

这一节是人工放大，不是另一套真实数据。学习和测试都把原 MNIST 用 2×2 最近邻放大到 56×56，再做和 P21 相同的掩码。只比了 P21 里高预算最短的按行，以及二维。学习 300 张，测试 1000 张，3136000 格。两边都学满 1024 条，逐张还原通过。Hilbert 在这里没有再跑。

放大之后，二维的 token 可以短过按行，合计比特也可以更低。这和原图 28×28 的结果不同。bin128 上二维在 64 条和 256 条两项都领先；1024 条时按行略短，token 31654 对 32170，合计 0.1047 对 0.1052。这一掩码的按位打包 zlib 是 0.0949，按行和二维都没有低于它。4level 上二维在三个预算的 token 和合计比特都低于按行，合计也低于按位打包 zlib 0.1784：64 条 0.1582，256 条 0.1442，1024 条 0.1456。1024 条时二维 46719 个 token，按行 68821 个，大约少 32%。

字典几乎都是紧凑块。bin128、1024 条：长条 2、紧凑块 968、其他 54，面积中位数 64，最大面积 1952。4level、1024 条：长条 4、紧凑块 955、其他 65，中位数 36。长条替换从 64 条起就固定在 1568000 次，等于 1000 张 × 56 行 × 28 对。这和最近邻把每个像素横着复制成相邻两格的数量一致，后面的预算没有再增加这类替换。紧凑块替换大约 151 万到 153 万次，和长条差不多各占一半。原图上紧凑块只占大约两成替换；放大图上各占一半，二维才在 token 上领先。因此这组领先说明的是“图被放大、同色块变大以后二维用得上”，不是原尺寸 MNIST 的结果。
