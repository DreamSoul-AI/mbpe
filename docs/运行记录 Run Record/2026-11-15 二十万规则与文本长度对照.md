# 二十万规则与文本长度对照

## 任务与协议

用户要求对照既有文本长度，并将 RGB 规则数从 150,000 扩到 200,000。只用 CPU，不改变颜色、扫描或输入合同。新脚本为 `studies/color_vocab_extension.py`，采用 `train → evaluate → decode` 三个独立阶段，完整实际命令、PID、耗时、退出码保存在本机 `tmp/2026-11-15-color-200k/stages.json`；全部退出 0。

沿用 E1 各 1000 张学习图；测试沿用上轮 H2 各 1000 张，没有用测试学习规则。H2 已曝光，本次是用户指定预算后的配对扩展，**不是新留出的独立确认**。预算和全部条件在 protocol.json 写明，源码复制进 source，所有候选先学完并封存在 run/sealed.json，再打开测试数组。每种表示重新学至 200,000 合并，取 150,000/200,000 前缀；四套词表的 150,000 前缀与上轮词表和编号完全一致，对应全部逐图长度也一致。

条件为原通道/可逆颜色坐标、150,000/200,000 规则、原 BPE/同词表最短解析，共每数据集八种。颜色坐标、逐行左差分、按列展开均沿用上一轮，未做量化。基础字母表 256，每套词表实际达到请求预算，20 万规则对应 200,256 个词条。

由 15 万到 20 万，颜色＋最短解析的 CIFAR/SVHN 相对上一档再少 1.709%/1.290% 位置；相对原始长度的节省增加 0.507/0.265 个百分点。不是再少 20 或 30 个百分点。

## 环境、资源与证据

沿用既有 Python 3.13.9、NumPy 2.5.4、tokenizers 0.22.2，不安装依赖。每个实验进程为 Idle、一个逻辑 CPU、线程库各 1、worker 0；启动和运行中检查内存，系统可用少于 4 GiB 或自身 RSS 超过 8 GiB 终止自身作业。临时文件本 repo/tmp，不使用 GPU，不改官方或 legacy，不提交推送。

本机输出根 `tmp/2026-11-15-color-200k/`：protocol.json、run.py、source、train/evaluate/decode.log、stages.json、run/sealed.json、run/各数据集/report.json、*.npz、independent-decode.json、analysis.json。原件 Git 忽略，未发布；不是读者克隆后自带数据。新流程通过上述真实输入、前缀恒等和独立恢复检查；本次未再次运行此前 76 项完整回归，原有公共 codec 未改。
