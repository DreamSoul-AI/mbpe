## 输入与计费合同

192 维 BF16，每维表示一个 0–255 字节值。RGB BPE 输入含 6 字节通道 token 计数头、9 位 token 流和向量尾部补齐。raw 固定分组为每图 16 位置、6,144 字节；BPE 词表和固定形状/容量/变换为共享合同，不使用逐图免费选择信息。

E4 每批 16 张，实配 BF16 张量 `[B,Lmax,192]`，另分配 bool mask `[B,Lmax]` 和 int32 长度 `[B]`。模型输入字节为 `384*B*Lmax + B*Lmax + 4*B`，最后不足 16 的批仍按真实 B。固定分组 1,000 张合计 6,164,000 字节。各策略均有相同口径的 mask/长度。

窗口只做稳定排序与各批分别补齐，不跨样本拼接。队列中 BF16 载荷峰值、最多暂存图数、最大等待后续到达图数另外报告；Python 容器、整个研究进程内存及宿主身份映射不属于上述模型输入。每图宿主身份 uint32 共 4,000 字节；帧头属于保存格式，不能把其文件大小当作激活大小。

编码阶段逐图还原；组批阶段实际构造和解包张量，逐格恢复。独立解码进程只读取保存的张量帧、共享词表和清单身份，不读取原图数组，恢复后比对冻结 RGB 哈希。E2 同样从独立保存的 BF16 位模式还原。所有被比较策略都保留完整 1,000 张。

## 环境、资源与命令

使用已有 `third_party/venv_mdbpe/Scripts/python.exe`，Python 3.13.9、NumPy 2.5.4；Torch 2.14.1+cu130 仅调用 CPU，不探测或使用 CUDA。SciPy 1.16.2、psutil 7.2.2。CPU 作业 Idle（优先级 64）、亲和性单逻辑核 0、库线程 1、worker 0；E4/E2 独立进程重叠时共享此核，时间不是公平速度基准。资源回执由各阶段保存。启动时可用内存约 23 GiB，每个研究入口要求至少 4 GiB，临时及输出均在仓库 tmp。
