# 2026-11-09 第11批平铺对照

只在清单版本 2 的 32×32 平铺格点上重做三项对照。宏观一节没有改。`merge_pair` 的选对没有改。

## 实验设定

| 项 | 取值 |
| --- | --- |
| 格点 | 版本 2 的 `tile`，32×32，4×4 小块平铺。种子决定小块里的 0–15 |
| 种子 | 0、1、2 |
| 配置 | 代码默认频率阈值，最大码字 `(1, 2, 2)`，批量 4。符号上限三档：不设、280、320。280 和 320 相对初始 256 个符号，分别还能新加 24 和 64 个 |
| 命令 | `python -m mbpe controls --seeds 0 1 2 --output results/2026-11-09-tile-controls-<配置>`。上限档加 `--max-symbols`。`--grid-name` 默认就是 `tile` |
| 硬件 | 与第 9 批同一台机器，`CUDA_VISIBLE_DEVICES=-1`。Python 3.13.9，torch 2.11.0+cu130 |
| 耗时 | 不设上限 4.613 秒，上限 280 为 1.867 秒，上限 320 为 2.487 秒。没有超过 20 分钟 |
| 测试 | `python tests/run.py` 25 项通过，1.713 秒 |

基线是 1024 个格子。门槛是长度下降并且无损还原。压缩比只作报告，不含词表正文。

三项对照不是同一条循环。停止和跳过使用训练出来的分词器。形状和空间项使用“一对至少出现两次才合并”的网格合并器，所以不设上限时它们可以收到 1 个 token，而分词器的频率阈值不会。

## 是否过门槛，三项能否分开

每一侧、每一个种子都比 1024 短，并且能还原，所以都过门槛。压缩比从大约 2 到 910，只说明剩下的 token 很少，不能当成压缩率。

不设上限时：停止和跳过只在种子 0 分开（240 对 1），种子 1 和 2 相同。unshuffle 稳定停在 2，两格星座停在 1。次数和空间项的长度都是 1，分不开，但词表大小不同，说明合并路径并不相同。

上限 280 时三项都能拉开长度。三个种子里，空间项都比纯次数更短（134、150、215 对 172、197、296）。跳过有时更短，种子 1 则与停止相同。

上限 320 时，停止和跳过的长度相同。unshuffle 仍是 2，星座停在 52–218。空间项在种子 1 和 2 更短，种子 0 反而略长（55 对 52）。

## 观察到的问题

- 不设上限时，平铺图案会让“至少重复两次才合并”一直走到底，次数和空间项都剩下 1 个 token。
- 跳过并不是稳定地更短。上限 320 时它和停止一样。
- 停止对照用的是频率阈值，另外两项用的是重复次数。两边的长度不能排成一张优劣表。
- 种子对停止后的长度影响很大：不设上限时是 240、1、40。

## 建议的下一步

1. 推荐：微观，把上限固定在 280，只在这张平铺格点上记下空间项和纯次数第一次选中不同的那一对，以及当时的 token 数。理由是不设上限时两边最后都是 1，长度没有信息；上限 280 时三个种子的空间项都更短，而且长度还远大于 1。仍不扫描 α、σ，也不改 `merge_pair`。
2. 微观：不要把跳过未知最大对写进现有循环。它只在部分种子上更短，上限 320 时又和停止完全一样。
3. 介观：报告时把分词器频率循环和“重复两次才合并”的网格循环分开。它们的停止规则不同，放在一个均值里会把 2 个 token 和 200 个 token 说成同一种结果。
