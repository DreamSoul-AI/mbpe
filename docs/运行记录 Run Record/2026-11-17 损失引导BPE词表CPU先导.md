# 损失引导 BPE 词表 CPU 先导

## 数据与运行条件

- CIFAR-10 固定 32×32 RGB，绿色中心颜色差分、横向一阶差分、按列扫描，通道之间单独切分。共享形状、变换和通道协议，起始词表是 256 个单字节。单规则和多轮均重新切分，按合并顺序从左到右进行非重叠替换。
- 首轮复用本地冻结数据，学习 1000 张，打分 128 张，测试 128 张，复核 372 张。四组按 RGB 哈希互斥。扩展实验复用学习和打分图，另从本地官方测试批抽取两组各 500 张，类均衡，排除首轮全部图像哈希及两组间的重复。
- Windows，仓库自有 Python 3.13.9 虚拟环境，NumPy 2.5.4，库版基线使用本地 Tokenizers 0.22.2。进程 Idle，单核、单线程，数据 worker 0。输出保存在仓库的 `tmp/2026-11-17-loss-guided-pair/`。`environment.json` 记录基线提交与本轮最终源码哈希。

## 合并选择与计量

单规则从训练实际替换次数排名第 1、33、129、513 开始各取 8 个候选。重复字节如 `00 00` 按从左到右的非重叠替换计数。每组频次选择取组内第一，loss 选择在打分集位置节省与第一名相差不超过 15% 的候选中取最低 loss。

多轮频次选择在当前切分上取实际可合并次数最高的对。loss 分支从前 16 个候选中取在学习集、打分集均保留至少 90% 当步频次最优候选位置收益的对。打分样本里至少 32 个目标出现预测上下文变化时，才允许按 loss 选择。各分支在同一规则预算上比较，逐图从 ID 独立展开，反变换后以原 RGB 的 SHA-256 核对。

预测器在学习数据的原始变换字节上建立计数，输出 256 类归一化字节概率。条件用前缀重切后最后一个 token 的原始展开，低支持度向较短后缀平滑。另测读取末尾两个 token 的敏感性。目标字节在重切时不可见。单规则使用全部可比较位置，首字节损失差按零计入。多轮每通道固定随机选 64 或 128 个目标，每个前缀最多 64 个原始字节。输入位置按全图计，192 维 BF16 每位置 384 字节。区间采用 10,000 次按图配对重采样，用于表示探索性不确定性。

最初从已有批次脚本导入完整流程时，虚拟环境缺该流程的 `tokenizers`。调整为复用轻量颜色与差分函数后通过。32 规则首启的通道分隔值 256 需先从 uint8 提升为 uint16，修正后重新运行并保留独立回执。全量离线检查首跑因 Windows 默认临时位置不可写失败，显式指定仓库内临时目录后通过。最终日志 `tests-final.log` 记录 88 项通过，其中 4 项为本轮定向回归。

## 结果与交叉核对

单规则在 128 张打分图及 500 张独立测试图上逐候选解码。扩展实验每种预测上下文各在两组共 1000 张图上核对，库版频次基线也使用这 1000 张图。汇总脚本 `summarize.py` 从逐图回执生成 `analysis.json`，包含位置、每字节 loss、按图配对区间和单规则档内排序。研究判断见[损失引导选词与频次 BPE](<../研究记录 Research Record/2026-11-17 损失引导选词与频次BPE.md>)。

初版与正式入口运行的库版频次 BPE 逐图一致。单 token 的直接切分和库重放在两组测试的 30 个词表检查点组合中，逐图位置全等，每字节 loss 误差小于 1e−12。双 token 的两种实现通过相同检查至 64 条规则。256 条规则学得的两支均有 512 个不同字节串词条。单 token 256 规则直接运行耗时约 34.5 分钟，峰值工作集 532.3 MiB。本轮有峰值记录的进程均低于 0.7 GiB。
