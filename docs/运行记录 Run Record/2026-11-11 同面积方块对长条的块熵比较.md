# 2026-11-11 同面积方块对长条的块熵比较

时间：2026-11-11 23:55（Asia/Shanghai）。巡检在第30批运行期间并行做的只读统计，未跑 BPE、未改代码、未用 GPU、未下载数据。接《真实小字母表数据MNIST二维上限》。

## 为什么做
上下文下界说明二维“有空间”，但 BPE 是把一整块相同的样式换成一个 token，它更关心的是：**同样面积的格子，摆成紧凑方块是否比摆成一维长条更常见、更好预测**。如果方块的种类更集中、整块同色更常见，二维形状的 token 才有可能比一维 token 更省。

## 做法
- 数据：MNIST（训练前 10000 张统计、测试前 2000 张测）；CIFAR 红通道 1000 张（前 500 统计、后 500 测）。掩码 bin128（≥128 记 1）与 4level（整除 64）。
- 把图按固定网格切成不重叠的块（1×2、2×1、1×4、4×1、2×2、1×8、2×4、4×2、1×16、4×4），把每块当一个“词”，算测试块的留出交叉熵（加 0.5 平滑）再除以面积，得到每格比特；同时记“整块同一取值”的比例和最常见 64/256 种块覆盖了多少块。
- 脚本与原始数字：巡检临时目录 grokbot\mbpe\blockent\（blockent.py、blockent.json、out.txt）。

## 结果（每格比特；括号内为整块同一取值的比例）

| 数据 | 面积 4：最好长条 → 2×2 | 面积 8：长条 1×8 → 最好 2×4/4×2 | 面积 16：长条 1×16 → 4×4 |
|---|---|---|---|
| MNIST bin128 | 0.349 (83%) → 0.331 (87%)，省 5% | 0.369 (62%) → 0.278 (78%)，省 25% | 0.285 (40%) → 0.231 (69%)，省 19% |
| MNIST 4level | 0.526 (80%) → 0.511 (82%)，省 3% | 0.550 (59%) → 0.429 (74%)，省 22% | 0.437 (37%) → 0.345 (67%)，省 21% |
| CIFAR 红 bin128 | 0.596 (75%) → 0.570 (79%)，省 4% | 0.524 (57%) → 0.475 (66%)，省 9% | 0.480 (35%) → 0.403 (51%)，省 16% |
| CIFAR 红 4level | 1.170 (56%) → 1.129 (59%)，省 4% | 1.028 (33%) → 0.942 (41%)，省 8% | 0.815 (15%) → 0.719 (26%)，省 12% |

## 结论
1. 在所有四种掩码上，同面积的紧凑方块都比一维长条更好预测，而且**块越大，二维优势越明显**：面积 4 只省 3%–5%，面积 8 和 16 省约 8%–25%。
2. “整块同一取值”的比例差距最直观：MNIST 二值上 4×4 方块 69% 是整块同色，1×16 长条只有 40%。这正是精确合并的 BPE 能吃到的部分，说明二维 token 的好处主要来自**大一点的紧凑形状**，而不是第一步的横向或纵向一对。
3. 对 BPE 的含义：二维 BPE 每次只合并一对，前几步横向一对和纵向一对差不多（面积 4 时只差几个百分点），所以在规则数少、图小时看不出二维优势；要到规则能长成 2×4、4×4 这样的块时差距才拉开。这可以解释为什么第29批原始像素上二维规则几乎都是横向一对、看不出好处，也提示第30批在预算 64 时二维可能领先不多，到 256、1024 才更明显（待第30批实测验证）。
4. 真实 MNIST 上二维优势大于 CIFAR 人工掩码，进一步支持把真实小字母表数据作为主战场。

## 注意
- 这里是固定网格切块的块熵，不是 BPE；4×4、1×16 在 4level 上种类很多，平滑会高估比特，所以只适合同面积之间比较，不要拿绝对值和 BPE 或 zlib 直接比。
- 只看了轴对齐的规则块，没有看任意形状。
