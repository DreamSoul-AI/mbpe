# 2026-11-11 第30批掩码上的一维与二维

只做 CPU。新原件在 `D:/Grok Bot/tmp/mbpe-20261111-round6/`。比较脚本是 `src/batch30_mask_baselines.py`，官方掩码脚本是 `src/batch30_elsner_mask.py`，合成图脚本是 `src/batch30_synthetic_shapes.py`。都没有改候选和官方代码的默认行为。进程最低优先级，数值库各 1 个线程。二维还原是字典和 packet 做 JSON 往返后逐格比对。普通一维是把 token 按规则展开后和原序列逐项比对。下面 P17 和 P20 的失败数都是 0。

掩码和只读统计用的是同一定义，作用在第27、28批同一批图上。bin128：像素大于等于 128 为 1，否则 0。bin_permedian：每张图用自己的中位数，大于等于中位数为 1。4level：像素整除 64，得到 0 到 3。CIFAR 学习图仍是每类前 30 张、共 300 张。测试是 paired 的 100 张和同一套 1000 张。SVHN、CelebA 仍是原来的 10 张学习和 100、90 张测试。

普通一维 BPE 与第29批相同：只合并相邻一对，次数小于 2 就停，并列时取字典序较小的一对，从左到右不重叠替换。新符号从字母表大小起，二值是 2，四级是 4，不再从 256 起。四种顺序仍是按行、按列、蛇形和 Hilbert。预算 64、256、1024 是同一次学习的前缀；没学满就写下实际条数。

合计比特沿用第29批的结构，字典对这一组测试图只算一次。字母表位图改成 2 位或 4 位，符号号宽度按“字母表大小加规则数”计算。二维每条规则仍加每个维度 6 位位移。一维每张图加 16 位长度和一个域标志；二维加 16 位形状和一个域标志。一阶估计仍是每张图第一个 token 的零阶熵，加上同一张图里后一个 token 在前一个条件下的熵，再加同一份字典和边信息。条件表没有另计比特，也没有做成编码器。zlib 等级 9 有两种存法：每个格子一个字节，以及按位打包（二值 8 格一字节，四级 4 格一字节）后再压。原始零阶熵按格子的取值算，不按字节算。

## P17 真实掩码

真实掩码上，二维没有短过 Hilbert。Hilbert 在每一组、每一个预算上都是最短的一维，也短于二维。二维短过的是一些更差的一维顺序：CIFAR 四级掩码上的按列，以及 SVHN 上的按行和蛇形。CelebA 上二维比四种一维都长。差距不是一点点。红通道 1000 张、bin128、64 条，Hilbert 是 8.3641%（85648 个 token），二维是 10.6840%（109404）。二维多出约 2.32 个百分点，大约多四分之一的 token。四级掩码上这个差距还在，二维仍然长于 Hilbert、蛇形和按行。

只读统计里“左加上下文比最好一维少四分之一到三分之一比特”，没有变成这次 BPE 的 token 优势。二维候选确实学到了比第29批更多的纵向规则，但测试时真正替换成功的仍以横向为主，见 P19。

1000 张上字典只算一次之后，二值掩码的合计比特大多仍高于按位打包的 zlib。唯一低于它的二值格子是绿通道中位数二值、Hilbert、256 条：0.5560 对 0.5588。四级掩码上 Hilbert 在 256 条和 1024 条低于按位打包的 zlib：红 0.9832 和 0.9633，对照 1.0306；绿 0.9701 和 0.9499，对照 1.0181；蓝 0.9387 和 0.9183，对照 0.9823。二维的合计比特没有低于打包 zlib。一阶估计更低，那只是 token 流自己的条件熵，不是压出来的文件。

## P20 更大的合成形状

真实掩码里二维相对最好一维亏得最少的是四级，不是二值。于是用四级字母表做了 64×64 的合成图，不再用 CIFAR 像素。种子 20261111。每张图先全 0，再画 4 到 8 个轴对齐矩形和 2 到 5 个圆盘，每个形状随机涂成 1、2 或 3。学习 64 张，测试另外 64 张。64 张都还原。

图变大、形状变整之后，二维的 token 才短过 Hilbert，而且预算越高超得越多。64 条时二维仍比 Hilbert 长（6.3843% 对 5.3062%）。256 条时二维 3.8437%，Hilbert 3.8834%，只短 104 个 token。1024 条时二维 2.6958%（7067），Hilbert 3.0659%（8037），大约少一成二。按行、按列、蛇形在这两个预算上都更长。

合计比特没有跟着赢。1024 条时 Hilbert 是 0.3558 比特/格，二维是 0.3759。二维字典要记位移，token 省下来的比特不够付这项。方向上也更能看出变化：1024 条里横向 315、纵向 351、其他 358，不再几乎全是横向。可是测试替换仍是横向 181860、纵向 71822、其他只有 1395。其他方向的规则学了不少，真正用上的很少。

## 结论

在 CIFAR、SVHN、CelebA 这三种由像素阈值化来的掩码上，二维候选没有短过最好的一维。最好的一维是 Hilbert，不是第29批原始像素上的按行或蛇形。二维只短过一部分较差的展平顺序。官方 Elsner 在同样的 300 张、64 条、红通道两种掩码上 token 更长，而且 64 条时自己的还原大面积失败。只有把图换成更大的矩形和圆盘之后，二维的 token 才在 256 条和 1024 条上短过 Hilbert；按第29批的合计比特口径，Hilbert 仍然更省。
