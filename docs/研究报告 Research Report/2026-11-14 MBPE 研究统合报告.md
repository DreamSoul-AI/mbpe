## 四组数据进入模型要占多少位置

基准是文本每个 Unicode 码点一个位置，图像每个单通道像素一个位置。BPE 后每个内容 token 占一个位置。总位置等于内容位置加上实际送进模型的坐标、形状、有效域、方向和分隔位置，比较两边各自计数。

下表假设输入前端提供固定外框、扫描方式和样本边界。二维坐标由词表的完整形状和覆盖顺序恢复，固定扫描的坐标由扫描次序确定，因此本表的额外位置为零。位移随词表共享。 [MNIST 隐式坐标往返](<../运行记录 Run Record/2026-11-14 MNIST BPE 定宽落盘对照.md>) · [第 38 批无损文件](<../运行记录 Run Record/2026-11-13 第38批 原始像素完整文件对照.md>)

### 输入激活的显存换算

把进入第一层的 embedding 张量作为输入激活。固定向量宽度为 192、精度为 BF16，每个位置占 192 × 2 = **384 字节**。单次输入占用为批大小 × 实际分配的序列长度 × 384 字节。主表按单样本、无填充计算。

| 数据和切词 | 原始位置 → 内容 + 额外 | 少了多少位置 | 单次输入激活 MiB |
| --- | ---: | ---: | ---: |
| 中文 Markdown 快照 · 千问 Qwen3 BPE | 9,149 → 5,903 + 0 | 3,246（35.48%） | 3.350 → 2.162 |
| WikiText-2 · 千问 Qwen3 BPE | 13,352,196 → 3,079,839 + 0 | 10,272,357（76.93%） | 1.500 → 0.346 |
| MNIST · Elsner 二维 256 条 | 7,840,000 → 1,452,248 + 0 | 6,387,752（81.48%） | 0.287 → 0.053 |
| CIFAR-10 · 原像素二维 256 条 | 102,400 → 95,297 + 0 | 7,103（6.94%） | 0.375 → 0.349 |
| CIFAR-10 · 左差分二维 256 条 | 102,400 → 78,395 + 0 | 24,005（23.44%） | 0.375 → 0.287 |
| CIFAR-10 · 蛇形 256 条 | 102,400 → 94,780 + 0 | 7,620（7.44%） | 0.375 → 0.347 |
| SVHN · 原像素二维 256 条 | 102,400 → 92,698 + 0 | 9,702（9.47%） | 0.375 → 0.339 |
| SVHN · 左差分二维 256 条 | 102,400 → 65,956 + 0 | 36,444（35.59%） | 0.375 → 0.242 |
| SVHN · 按列 256 条 | 102,400 → 92,655 + 0 | 9,745（9.52%） | 0.375 → 0.339 |

中文 Markdown 用当时保存的完整快照，字符数按 Unicode 码点计，含空格和换行。WikiText-2 的位置总数来自 raw 的三个划分，单次激活用 4,096 个原始字符按全量比例折算，约为 945 个 token。图像按单张平均长度换算，MNIST 为 10,000 张 28×28 灰度图，CIFAR-10 和 SVHN 各为 100 张 32×32 原始绿通道图。 [中文文档与 MNIST 实测](<../运行记录 Run Record/2026-11-14 MNIST BPE 定宽落盘对照.md>) · [WikiText 实测](<../运行记录 Run Record/2026-11-14 WikiText BPE 定宽落盘.md>) · [原始绿通道实测](<../运行记录 Run Record/2026-11-13 第38批 原始像素完整文件对照.md>)

输入长度缩短后，按位置保存且每位置宽度相同的激活会同比缩小。训练时保留的中间激活和推理 KV 缓存取决于具体实现。实际 GPU 激活峰值待测，批次填充、注意力实现和重计算会影响实占。

两套原始绿通道先做逐行左差分，再用同样的二维算法学 256 条规则，相对原像素二维 BPE 分别再少 **17.74%** 和 **28.85%** 的位置。两套各 100 张测试图都逐像素还原。以原始像素长度为分母，达到减半的分别只有 2 张和 3 张。 [左差分实测](<../运行记录 Run Record/2026-11-14 原始像素与左差分 BPE 对照.md>)

### 固定分块的模型输入对照

ViT 将不重叠的图像块展开，每块映射成一个向量。块边长为 $P$ 时，每张图有 $HW/P^2$ 个位置，本次尺寸均能整除。用上面相同的 192 维 BF16 输入和固定模型做对照，把块内像素直接放在向量前几维，其余补零。固定外框、块大小和扫描顺序确定位置，额外位置为零。 [ViT 原论文 §3.1](https://openreview.net/pdf?id=YicbFdNTTy) · [BF16 分块还原记录](<../运行记录 Run Record/2026-11-14 固定分块的模型输入对照.md>)

| 同一份 32×32 绿通道 | 位置/图 | 输入激活 KiB/图 |
| --- | ---: | ---: |
| CIFAR-10 二维 BPE，256 条 | 952.97 | 357.36 |
| SVHN 二维 BPE，256 条 | 926.98 | 347.62 |
| 两套数据，2×2 分块 | 256 | 96 |
| 两套数据，4×4 分块 | 64 | 24 |
| 两套数据，8×8 分块 | 16 | 6 |

4×4 分块比当前二维 BPE 少用 **93.28%**（CIFAR-10）和 **93.10%**（SVHN）的向量位置。MNIST 同批 10,000 张图用 4×4 分块为 **49 个位置/图**，二维 BPE 平均为 145.22。第 40 批的 16×24 RGB 裁块用 8×8 分块只需 **6 个位置/图**，每个向量正好放 8×8×3 = 192 个像素分量。

若每张图都要达到 50%–70% 的位置降幅，固定分组已有确定的长度。1,024 个像素每 2 个一组剩 512 个位置，每 3 个一组剩 342 个位置，分别少 **50.00%** 和 **66.60%**。一个组用单个整数编号时，需要容纳 65,536 或 16,777,216 种组合，也可以把各分量直接装入同一个输入向量。固定分组的长度是图像上衡量 BPE 额外收益的基准。 [固定分组的逐图还原](<../运行记录 Run Record/2026-11-14 原始像素与左差分 BPE 对照.md>)

这组数字适用于一块一向量的直接填充，以及上表中一个 BPE token 对应一个向量的设定。还原从模型输入向量进行。学习投影后的逐像素可逆性和下游任务效果待验证。 [测试范围](<../运行记录 Run Record/2026-11-14 固定分块的模型输入对照.md>)

### 坐标和形状占位置时的成本

等容量打包的后续实测已将 9 位 BPE 编号、每图 token 数和尾部补齐计入。同一 192 维 BF16 向量只使用前 2 或 3 个字节值维度时，差分 BPE 相对固定像素分组在 CIFAR-10 再少约 14% 的位置，SVHN 再少约 27%。两套各 100 张逐像素还原。 [打包后的研究结论](<../研究记录 Research Record/2026-11-14 差分BPE打包后的输入位置收益.md>)

- **额外形状位置。** 如果只在二维 BPE 一侧每张图送一个形状向量，MNIST、CIFAR-10、SVHN 分别变为 1,462,248、95,397、92,798 个位置，分别省 **81.35%、6.84%、9.38%**。任意外框和带孔域所需的位置按实际模型输入计。
- **额外坐标位置。** 如果每个内容 token 另配一个坐标向量，三组二维序列分别变为 2,904,496、190,594、185,396 个位置。MNIST 仍省 **62.95%**，CIFAR-10 和 SVHN 则分别多 **86.13%** 和 **81.05%**。坐标可在模型前端计算并用于同一个向量位置时，额外序列位置为零，坐标缓冲和计算另计。
- **三维的净收益。** 第 40 批的 40 个稠密 RGB 裁块，256 条规则时线性扫描为 44,475 个内容位置，几何 BPE 为 44,146 个。外框由前端提供、几何位移由共享词表恢复时，几何 BPE 少 329 个位置（0.74%）。几何端比线性端多占 329 个辅助位置时，两者打平。 [三维数据和位移](<../运行记录 Run Record/2026-11-14 第40批 任意形状文件与线性对照.md>)

### 公开实现的两类无损问题

- **Zhang 侧的后续 Being-VL-0.5 快照可以在 CPU 上单独切词。** 固定快照 `e92ce36` 的 BPE 核心对已有整数格子可以学习和编码，原命令入口在合并后访问缺失字段而退出。最小脚本直接调用公开代码，两张不同的 2×2 格子得到同一序列 `[256, 3, 4]`。每通道 1,000 张 CIFAR-10 输入中，红、绿、蓝分别有 119、135、180 张存在另一张同输出的合法格子。这些替代格子由实验构造，再交给公开代码重编码确认。另存首轮每次合并的横竖方向后，3,000 次逐图还原全部通过，原 token 不变。数字适用于这个固定快照和样本，旧论文对应的固定实现仍待核对。 [独立 CPU 切词](<../运行记录 Run Record/2026-11-11 Zhang独立CPU切词.md>) · [反例、前像检查与修复](<../运行记录 Run Record/2026-11-11 碰撞复现与同输入对比.md>)
- **Elsner 笔记本在 CelebA 上的两次失败定位到形状导出。** 有些规则形状的下方格点伸到锚点左侧，导出只记一个轴的偏移时会铺错位置。这个现象在手工 4×4 例子上复现。CelebA 的原序列和规则可以用完整位移外部还原 90/90。同一批 CIFAR-10 每通道 1,000 张原像素上，Elsner 原生还原均通过。二值 MNIST 的另一个配置有 84/100 张原生还原失败。 [形状导出最小例](<../运行记录 Run Record/2026-11-11 第27批 Elsner形状导出最小例.md>) · [同输入对照](<../运行记录 Run Record/2026-11-11 碰撞复现与同输入对比.md>) · [二值 MNIST 官方对照](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>)

两种公开实现用每通道同 10 张学习、同 1,000 张测试、256 条规则时，Elsner 的红绿蓝剩余比例为 96.64%、96.43%、96.46%，Zhang 快照为 97.16%、96.99%、96.71%。这组长度只数 token。还原需要的锚点、位移和方向信息应进入字节比较。 [同输入正式对照](<../运行记录 Run Record/2026-11-11 碰撞复现与同输入对比.md>)

自有二维候选与 Elsner 在相同的 10 张学习图、1,000 张测试图及 256 条规则下，三个通道的剩余比例相差约 0.03–0.20 个百分点。候选增加到 300 张学习图后序列进一步缩短，Elsner 仍用 10 张词表。这组差异可用于判断候选的学习规模效应。 [候选与官方对照](<../运行记录 Run Record/2026-11-11 第28批规模与任意形状.md>)

## 矩形、带孔和三维文件已通过无损还原

候选保存外框、有效格点、几何规则和未见整数。每条规则保存两个子符号及各轴相对位移。编码区域始终互不重叠，覆盖全部有效格点，内容与对应规则一致。只要实现保持这些条件，并以每个区域坐标顺序最小的格点为锚，解码器就能把下一个 token 放在首个未覆盖的有效格点。由此可推导固定合法词表下的无碰撞性。 [无损条件与推导](<../研究记录 Research Record/2026-11-11 无损合同形式化与碰撞条件.md>)

### 规则预算与样本规模

CIFAR-10 的频次版候选在 256 条规则下，固定测试集，把学习图从 10 张增加到 300 张，三通道平均剩余 token 从 96.40% 降到 93.39%。在事前选定的 300 张主对照中，可同时替换数、跨图支持度和留出验证计分都未缩短独立测试的 token，频次法保留为参照。更早的小型平铺对照中，空间项在部分预算上有收益，实测范围是构造格子。 [学习规模和计分](<../运行记录 Run Record/2026-11-11 第27批候选对比与成本.md>) · [早期机制对照](<../开发记录 Development Record/2026-11-09 第14批收尾.md>)

### 每个 token 的码长和定宽打包

### 位移、有效域和三维基线

## 对论文路线的判断

**已经验证了能在独立真实数据上稳定少用模型位置的多维方法吗？** **否。** 当前证据覆盖无损还原、强一维对照和若干布局上的位置优势。Elsner 已涵盖多维、非凸形状与按覆盖推断锚点，Re-Pair 和图文法已有局部计数与索引方法。图像上的新方法需要在同一输入和同一向量宽度下通过固定分块与强一维对照。实际模型显存和任务质量需要模型侧验证。 [相关工作与贡献边界](<../调研 Search/文献调研 Literature Search/文献调研 Literature Search MBPE.md>)

1. **用真实少值格子验证位置收益。** 在独立的原生二值或标签格子上，和固定分块、验证集所选的强一维及零规则比较，逐项计入形状、有效域、坐标和方向需要占用的位置。保持无损还原和相同模型宽度，检查紧凑块与自动选向各能少用多少。 [研究计划](<../研究计划 Research Plan MBPE.md>)
2. **用现成三维序列检验几何开销。** 冻结第 40 批的词表和 token，比较由前端提供几何信息与单独占模型位置的做法，检查 329 个位置的优势能否保住。传输侧另测更紧凑的位移，在其他字节不变时，Huffman 的位移与新增开销需低于 135 字节，zlib 需低于 341 字节，才会小于对应线性文件。 [第 40 批成本](<../运行记录 Run Record/2026-11-14 第40批 任意形状文件与线性对照.md>)
