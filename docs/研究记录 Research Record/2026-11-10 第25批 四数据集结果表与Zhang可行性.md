## Zhang 2410.02155 的 BPE 能不能不用 GPU 直接跑

**能，前提是已有整数格子，并直接调用公开快照的 BPE 核心。** 这是后续在 CPU 上实跑的结论。第 25 批当时只读了论文和仓库说明。 [后续实跑](<../运行记录 Run Record/2026-11-11 Zhang独立CPU切词.md>)

论文里的 BPE 吃的是已经量化好的格子：Chameleon 的 VQ-GAN，码本 8192，每张图 1024 个编号（32×32）。附录写实验机器是 8 块 A800。合并算法本身是在这些整数上数相邻对。

[Being-VL-0](https://github.com/BeingBeyond/Being-VL-0) 现在只剩 README，写明代码已经迁到 [Being-VL-0.5](https://github.com/BeingBeyond/Being-VL-0.5)。0.5 的 README 对应的是后一篇 2506.23639，并写代码从开发版重构过来、未必全部测过。不能把它当成 2410.02155 的现成复现包。

0.5 的数据说明里，合并脚本 `beingvl/train/train_vbpe.py` 只读一个形状为「张数 × 32 × 32」的整数文件，脚本参数里没有显卡。对应实现用的是 NumPy 和 Numba，不是 CUDA。这个文件要先用 VQ-GAN 编出来；说明里的编码例子会加载量化模型。后面的三阶段训练脚本则写明用显卡（bf16、tf32，以及传入卡号）。

所以：整数格子已经在手时，公开的合并脚本按说明可以不靠 GPU。从原图直接跑他们的 BPE，公开仓库没有一条只靠 CPU、又标明是 2410.02155 的入口。本批没有去跑。
