# 第 39 批打包位宽改变压缩排序

## 总览

1. **统一到 9 位后，零规则仍比 256 条固定扫描小吗？** **否。** CIFAR-10 和 SVHN 都是 256 条固定扫描的 zlib 文件更小。按原宽写盘时，两套数据都是零规则更小。
2. **统一位宽后，256 条合成格子的自动选向仍比二维小吗？** **否。** 紧凑块和混合长条均由二维更小。混合长条 64 条统一到 7 位后，自动选向仍小于二维。
3. **重打包文件都能逐格还原吗？** **是。** 新写的 22 个文件均通过。 [运行记录](<../运行记录 Run Record/2026-11-14 第39批 固定切词与统一位宽.md>)

## 分项证据

### 零规则和非零规则的排序取决于位宽

- **依据。** 统一 9 位后，CIFAR-10 固定扫描从零规则 114,707 字节降至 256 条的 109,182 字节。SVHN 从 113,676 降至 106,469 字节。原宽文件中两组均由零规则更小。
- **适用范围。** 原始 8 位绿通道，各档保留原验证集选出的扫描和 token。统一位宽回答打包差异对这组排序的影响。
- **待验证。** 在不同编码后端、原生标签或更大规模上，非零规则能否以实际部署格式占优。 [完整文件表](<../运行记录 Run Record/2026-11-14 第39批 固定切词与统一位宽.md>)

### 合成长条的自动选向结果分预算

- **依据。** 256 条长条上，自动选向用 8 位时为 10,766 字节，改 9 位为 17,980 字节。二维为 14,494 字节。64 条统一 7 位后，自动选向仍为 18,127 字节，小于二维 19,596 字节。改动仅在自动选向数据块。
- **适用范围。** 第 35 批冻结的四级长条和紧凑格子，第 37 批总规则数相同的词表。
- **待验证。** 原生低字母表格子上，压缩后 token 的排列规律是否也产生类似效果。 [迁移、位宽和逐格验收](<../运行记录 Run Record/2026-11-14 第39批 固定切词与统一位宽.md>)
