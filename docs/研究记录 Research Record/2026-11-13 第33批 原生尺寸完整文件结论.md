# 第 33 批原生尺寸完整文件结论

## 总览

1. **二维的完整文件比 Hilbert 小吗？** **否。** 两种掩码都是零规则 Hilbert 加打包 zlib 最小。只看验证集选出的非零规则配置，Hilbert 也比二维小。
2. **二维多出的字节主要来自位移吗？** **否。** 差距主要来自压缩后的 token 数据块。
3. **完整文件能逐格还原吗？** **是。** 这批未缩放的 CelebA 裁块掩码全部通过。跨身份和原生二值或标签数据尚未验证。

## 分项证据

### 完整文件排序

- **依据。** 四级测试集中，Hilbert 零规则为 40,416 字节，按行打包 zlib 为 42,803 字节。二值分别为 17,524 和 19,358 字节。二维的验证集最优配置也是零规则，大小等于按行打包 zlib。只比较非零规则时，四级二维为 52,723 字节，Hilbert 为 45,743 字节。二值为 26,594 对 18,897 字节。 [第 33 批运行记录](<../运行记录 Run Record/2026-11-13 第33批 CelebA完整文件对照.md>)
- **适用范围。** 128×128 原像素间距的裁块、二值和四级掩码、0/64/256 条规则、定宽打包与逐图 zlib。非零规则的配置由验证集选定，四级两边均为 256 条，二值为二维 64 条与 Hilbert 256 条。
- **待验证。** 使用相同的其他 token 编码后端时排序是否保持，以及独立原生离散数据上能否复现结果。

### 字节差主要出在压缩数据块

- **依据。** 四级非零规则对照中，二维多出 6,980 字节，其中 6,468 来自数据块，512 来自位移。二值二维的固定开销少 336 字节，数据块多 8,033 字节，净差 +7,697。两组二维的实际替换中，紧凑块分别约占 4.37% 和 2.76%。 [字节分项与替换计数](<../运行记录 Run Record/2026-11-13 第33批 CelebA完整文件对照.md>)
- **适用范围。** 当前固定宽度 token 表示、共享字典、逐图压缩和各自的验证集所选配置。
- **待验证。** 冻结现有切词后，等条件更换两边的 token 编码后端，可以检验差距主要来自切词还是打包后的数据规律。紧凑块占比只提供诊断线索。
