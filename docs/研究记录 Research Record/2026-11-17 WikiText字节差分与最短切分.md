# WikiText 字节差分与最短切分

## 同规模词表下，一阶差分能缩短文本吗？

本次三个规模下，差分都让输入变长。原始 UTF-8 和字节差分各在同一 WikiText-2 训练划分上学习 BPE 词表，同一测试划分评估。两组共享原文的行边界及字节字母表。

| 实际词表项 | 原字节普通 BPE | 差分普通 BPE | 原字节最短切分 | 差分最短切分 | 差分最短相对原字节最短 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 32,768 | 227,579 | 243,362 | 220,675 | 239,334 | +8.46% |
| 100,000 | 193,976 | 201,279 | 187,239 | 196,987 | +5.21% |
| 151,643 | 185,914 | 191,678 | 178,965 | 187,067 | +4.53% |

差分用当前字节减前一个字节，使用模 256，首字节保留。差分连续跨换行，BPE 两组均只在原文行内合并。最大档中，原字节和差分的最短切分分别比同词表的普通 BPE 少 3.74% 和 2.41%。测量单位是 token 位置。全部条件逐字节还原，本次比较适用于该语料与切分设置。

## 和原装千问三比是多少？

原装 Qwen3-0.6B tokenizer 的基础词表有 151,643 项，同一测试文本得到 **299,078 个 token**。以 1,288,556 个 Unicode 码点作原始位置，千问减少 76.79%，本地同规模原字节最短切分减少 86.11%，差分最短切分减少 85.48%。

本地词表在 WikiText-2 训练划分上专门拟合，并允许在同一行跨词合并。与千问的差距包含学习语料和预切分的差异。同一行边界下的原字节与差分比较隔离了差分的作用。[之前对齐千问预切分的实验](<../运行记录 Run Record/2026-11-14 WikiText 千问与本地 BPE 对照.md>)
