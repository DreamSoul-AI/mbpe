# 第 35 批形状与二维切词结论

## 总览

1. **二维在紧凑块和长条上都比 Hilbert 切得更短吗？** **是。** 两种布局都少留 token，长条上的相对优势更大。
2. **二维完整文件比同预算 Hilbert 小吗？** **是。** 两种布局的 Huffman 和 zlib 都更小。和零规则按行打包 zlib 比，二维 256 条加 zlib 只在紧凑块上更小。
3. **两种布局的文件都能逐格还原吗？** **是。** 832 次检查全部通过。压缩排序来自四级合成格子。

## 分项证据

### 二维在两种布局上都少留 token，长条的相对优势更大

- **依据。** 256 条时，紧凑块二维和 Hilbert 分别剩 10,097 和 57,473 个 token，长条分别为 11,169 和 75,551。两布局的「二维减 Hilbert」之差为 +17,006 个 token，配对区间 [12,722, 21,595]。64 条时方向一致。紧凑布局中紧凑规则的实际替换占比更高，但它的相对 token 优势更小。 [第 35 批配对差及替换计数](<../运行记录 Run Record/2026-11-13 第35批 紧凑块与长条对照.md>)
- **适用范围。** 128×128 四级格子、等直方图、16 格图案、平衡横竖方向以及已测的两档规则预算。
- **待验证。** 更换长宽比或扫描顺序后，排序是否保持。当前形状变化也会改变边界和 Hilbert 路径上的连贯性。

### 对 Hilbert 的文件优势在两种编码中都出现

- **依据。** 256 条时，紧凑块 Huffman 文件是 10,472 对 53,979 字节，长条是 11,809 对 72,119 字节，两组的 zlib 排序相同。按行打包 zlib 在紧凑块为 15,840 字节，长条为 13,542 字节。对应的二维 256 条加 zlib 分别为 13,082 与 14,290 字节。 [完整文件与零规则对照](<../运行记录 Run Record/2026-11-13 第35批 紧凑块与长条对照.md>)
- **适用范围。** 完整文件包含词表、位移、码表和块头。零规则时，按行与 Hilbert 的 zlib 文件大小已有差距。扣除该差后，256 条的 zlib 布局交互区间跨零。
- **待验证。** 按行、按列或蛇形 BPE 在等预算下能否利用长条，缩小二维相对最佳一维的差距。

### 两种布局均可从文件逐格恢复

- **依据。** 26 个文件、共 832 次独立解码全部通过。同配置的 zlib 与 Huffman 文件读回同一串 token。 [逐格验收与原件](<../运行记录 Run Record/2026-11-13 第35批 紧凑块与长条对照.md>)
- **适用范围。** 稠密四级方格及现有研究文件格式。
- **待验证。** 原生二值或整数标签格子，以及任意形状的完整文件。
