# 第 37 批逐图自动选向方案

第 36 批在已知长条方向时，按行或按列能解释大部分二维相对 Hilbert 的 token 差距。本批检验从格子本身选向时，收益能否覆盖第二套词表与码表。 [第 36 批研究结论](<../2026-11-13 第36批 扫描方向与二维优势.md>)

1. **冻结样本与切词。** 复用第 35 批学习、验证、测试划分，并核对输入清单和逐图哈希。按行、按列、验证集所选固定扫描及二维的词表、码表和 token 从第 35、36 批文件读取。每个布局仍有 16 张验证和 32 张测试图。
2. **验证集选一个阈值。** 对每张格子计算横向相等邻居数减纵向相等邻居数，分数大于等于阈值就按行，否则按列。候选覆盖验证分数的所有不同划分。用两种布局和 64、256 两档验证图的 Huffman 数据块字节之和选阈值，平手选离 0 最近者，再选较小者。自适应文件在每个预算都保存两套词表及码表，验证阶段这些开销随阈值保持相同。阈值写盘后，测试和两种后端共用这一条规则。测试选向只读取像素格子。
3. **完整文件比较。** 自适应每个文件保存两套等预算方向词表，Huffman 另存两张验证码表。每图一位方向标记，含文件头、块头和填充。对照为第 36 批按布局、预算及后端预选的固定一维，以及第 35 批二维。分别报告 token、字节分项和总字节。每对比较按测试图重采样 10,000 次，种子 37004，固定开销每次计一次。新文件由独立解码进程逐格比对。

主要判据为混合方向长条的完整 Huffman 文件。若自动选向相对固定扫描缩小文件，且对二维的差明显收窄，则支持扫描选择能解释第 36 批的混合方向差距。zlib、紧凑块和第二档规则用于检查条件依赖。每套方向词表各用 64 或 256 条，总规则数及其存储开销单列。 [第 36 批数据与计费](<../../运行记录 Run Record/2026-11-13 第36批 等预算扫描顺序对照.md>)

## 主对照后补充的总规则数检查

主对照完成后，保留冻结的选向规则和两种对照，把行列词表各截成 32 或 128 条，使每个文件合计仍为 64 或 256 条。按原验证集在截短序列上生成两张 Huffman 码表，沿用相同字节口径及逐格验收。此项检查阈值固定时，比较结论是否依赖每方向分配完整预算。
