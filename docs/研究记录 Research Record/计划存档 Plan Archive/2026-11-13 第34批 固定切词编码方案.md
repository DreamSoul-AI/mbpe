## 第 34 批：固定切词，替换编码方式

**问题。** 第 33 批的二维文件差距，换一种 token 编码还会有多大？假设是定宽打包加 zlib 放大了两边 token 数据块的差距。若同一批序列用规范 Huffman 后差距仍然接近，就要进一步检查规则生成了多少 token，以及 token 的频率分布。

1. **固定输入和规则。** 从第 33 批落盘文件提取并核对词表、token 与样本顺序。沿用 16 张验证和 32 张测试。四级主对照是二维 256 对 Hilbert 256。二值辅助先沿用验证集所选的二维 64 对 Hilbert 256，再补二维 64 对 Hilbert 64。缺少的 Hilbert 64 测试序列从已保存的零规则序列和 256 条词表前缀重放，用已存验证序列核对。按行打包 zlib 和 Hilbert 零规则继续引用第 33 批的实际文件。 [第 33 批运行记录](<../../运行记录 Run Record/2026-11-13 第33批 CelebA完整文件对照.md>)
2. **只改变 token 编码。** 每种配置用自己的验证集 token 频次加一，构造确定性的规范 Huffman 表。按符号编号写入码长，每份文件计一次表，保留原有共享词表、位移与逐图块边界。逐图编码并记填充字节。测试集不选词表、预算或码表。对照端沿用同一序列的定宽打包加 zlib，已有文件直接读，新增等预算对照按同一格式写出。
3. **先验收，再判读。** 独立解码需恢复每张格子的尺寸和值，读回的 token 也须逐项等于冻结序列。按掩码分别报告总字节差和数据块差，拆出编码表、词表与位移。报告每张数据块差及 10,000 次源文件配对重采样的区间，复用既有种子 20261113，固定开销每次计一次。以总字节差缩小至少一半或变号作为本批预设的敏感性信号，同时查看数据块差的变化。方向和量级相近时，优先检查切词与符号频率。若区间跨零，保留为未定。此处是同一批样本上的机制诊断，跨身份泛化待独立验证。

本批用 CPU 最低优先级，现有本地环境和原件，结果写入仓库 `tmp/` 下的新目录。后续用原生二值或少量整数标签数据独立核验，按原始文档划分。形状机制用同尺寸、同值频的紧凑块和长条对照。
