### 本轮候选：显式几何字典与可同时替换计数

竞争解释：仅拉平序列也能还原，所谓“通用”可能只来自额外保存坐标，而不是更好的合并。因此本轮小试验只回答表示合同是否成立，同时报告 token 数、锚点整数数量和规则字典成本，不声称压缩改进。使用水平/垂直二义反例，以及1D、非方形2D、带孔3D、4D和高维小格子，学习与应用分开，保留未见测试值。实验用纯 CPU 单线程，不改官方或 legacy。

若全部逐值、形状与覆盖还原正确且推理不改词表，则进入相同规则预算下“坐标表示成本”和“任意维邻接”的对照；若不成立先修表示，不加新的频率打分或下游模型。即使成立也只能说明工程可逆，不足以认定论文创新或优于 Elsner。

后续配对对照：保持同一个已学词表和同一个 token 划分，只改变锚点传输。A 显式保存每个 token 的 N 维锚点，B 按首个尚未覆盖的格点推导锚点，稠密区域只保存 shape，带孔区域另传1 bit/格的占用掩码。两臂必须产生完全相同的逐点重建；主要指标是实际 JSON 字节及坐标整数个数，词表成本单列。若省坐标仍不能抵消字典和掩码成本，则不宣称压缩收益。该技巧可能与已有 raster-order 位置机制等价，新颖性待查。

进一步核对 Elsner 第4节、第4.3节和第5.2节后，原文已经明确 n 维原则、非凸形状、由已覆盖区域推知下一位置，并给出3D体素。因此“多加维度”“允许非矩形”“推导锚点”均不能独立作为新贡献。当前原型仅把这些性质落实为可测试的统一接口。更值得小试的是稀疏区域邻接图是否能在严格保持同一合并序列时减少重复格点扫描。

邻接图事前对照：同样本、同频次统计、同并列与重叠顺序、同规则预算，只把每轮扫描全部格点改成维护区域边界图。图边保存最早格点/轴作为扫描见证，区域合并时只更新相邻边，保证候选顺序可与参考全扫描逐轮比较。主验收为每轮候选列表、规则、输出及还原完全相同，次指标为单线程实际用时与峰值边数。若序列不一致先拒绝提速结论，若只有大形状重复区域有效则明确适用条件；不以自实现之间的用时差宣称胜过官方 C++。

初次用时仅几十毫秒且不含建图，不能判断实际总收益。补充5次配对重复，覆盖32×32/64×64重复区域、32×32随机像素和带孔8³；计入两臂初始化，单列共同的规则选择工作。判断规则不改：候选/分组不一致立即失败；只对本原型已计时机制报告中位数范围，不外推官方实现速度或硬件泛化。

微观问题是合并循环本身。对照都在同一套格点接口里做，否则分数差异无法解释。

文献中的循环差异已经具体。一维 BPE 按语料次数选对，并保存合并顺序，推断时按该顺序执行。Re-Pair 合并到没有重复对。WordPiece 按语言模型似然。网格 BPE 同时数两个方向，停在额外词表规模。优先级变体是频率加空间一致性，α 和 σ 在开发集上选定。重叠在生成时被显式禁止。

仓库循环是另一套。它用次数除以总次数，取序列中第一次达到最大的对，该对不在词表就停止，不继续看更低的对。重叠从左吃掉，不复用。空对或尚无频次时停止。这些行为已有回归。2026-11-09 的对照说明其中几项会改变 token 数，但没有授权把循环改成论文算法。

四个对照已在 2026-11-09 跑完，网格和命令见运行记录。`merge_pair` 没有改。下面四条里“留到宏观”是 06:15 之前的说法，现只作辅助。

第一，次数和次数除以总次数在同一张 4×4 格点上选出同一串对，token 数相同，格点逐值还原。按停止规则，不为次数单独增加参数。文献默认 α = 0.3、σ = 2.0 的空间项用的是附录算法 2 的公式，没有扫描这两个数。次数打成 2 对 2、且先出现的对方向不一致时，空间项改选另一对：格点上由 `(1, 2)` 改成 `(2, 3)`，合并到不能再合并时 token 数从 12 变为 10，整数仍还原。次数是 5 对 1 时，即使高频对的方向不一致，空间项也不改选。长度会变，所以这项和下面两项一起留到宏观；没有开发集，不扫描 α、σ，也不写入合并循环。

第二，序列 `c d a b` 上，当前最大对 `(c, d)` 不在词表、`(a, b)` 在词表。现有循环停止，长度仍是 4。跳过未知最大对之后长度是 3，被合并的一项可以展开回 `(a, b)`。长度变了，所以这项留到宏观；现有循环继续停止。

第三，形状对照用同一条停止：一对至少出现两次才合并。手工 4×4 格点在 `(1, 2, 2)` 的 unshuffle 顺序里有重复对 `(1, 2)`，`State.merge` 一次后长度 14。同一格点上没有重复的水平或垂直相邻对，两格星座长度保持 16。两边都覆盖全部格子。另有一条不能混进来的结果：三个阈值都为 0 时，`Tokenizer.train` 把一张条纹图收成 1 个 token，并且可以解码回去。那是“只出现一次也合并”，不是形状对照。

第四，`a a a` 上，从左向右的非重叠合并与同样顺序的重叠禁止得到同一划分：前两格一组，最后一格单独留下。放置顺序改成从右向左时，划分变成第一格单独留下。两种划分都覆盖三个格子，token 数都是 2。顺序会改变分组，但本轮没有改变长度或逐格还原，所以不增加第二套重叠参数。

因此现有循环保持原样。合成格点上看到的停止还是跳过、unshuffle 序列还是两格星座，以及这一组已发表空间系数，从 2026-11-09 06:15 起只作微观辅助，不再称作宏观待比较清单。重叠顺序会改变分组，但 token 数不变。第 11 批只在版本 2 的 32×32 平铺格点上重做了这三项，见 [2026-11-09 第11批平铺对照](<../../运行记录 Run Record/2026-11-09 第11批平铺对照.md>)。不设上限时空间项的最终长度仍是 1；上限 280 时三项都能拉开长度。`merge_pair` 的选对没有改。第 12 批在同一上限下记下次数和空间项第一次分叉，见 [2026-11-09 第12批第一次分叉](<../../运行记录 Run Record/2026-11-09 第12批第一次分叉.md>)。三个种子的分叉步分别是 9、1、8。第 13 批给分叉补了成员、方向和得分，并在条纹、平铺、噪声上各跑了一次，见 [2026-11-09 第13批分叉标注](<../../运行记录 Run Record/2026-11-09 第13批分叉标注.md>)。空间项只在平铺上稳定更短。这些结果不能代替两篇论文的复现。

### 此前写在宏观和介观里的原文

下面两段是 2026-11-09 06:15 之前的原文，原样保留。它们不再是宏观或介观的目标。

此前的宏观：

宏观问题是：在离散视觉序列上，按内容合并出的变长 token，相对于固定网格，是否降低下游的序列代价，同时不把误差藏进量化器。

这个问题比较的是任务目标，不是某一个合并循环。生成文献用 FID 和收敛速度，理解文献用 VQA 一类基准。两边的模型、数据和优化器不同，不能合成一个胜负。宏观计划只保留三个分开的结果：序列长度、相对离散底稿的逐格误差、下游分数。词表、形状和位置如果另外传输，必须计入代价，否则长度下降不能叫做压缩。

会改变宏观判断的观察：在冻结量化器之后，合并不再缩短序列，或者缩短了但下游分数和固定网格没有可区分的差别。出现这种结果就停在表示层，不再加更复杂的合并分数。

微观对照里，有三项已经在合成格点上改变了 token 数，并且仍然逐格还原。一是未知的当前最大对：停止时序列长度为 4，跳到下一个已知对时长度为 3。二是覆盖形状：同一条“至少重复两次才合并”的停止下，`(1, 2, 2)` unshuffle 序列收成 14 个 token，两格星座保持 16 个。三是文献默认的空间项：同一张格点上，纯次数停在 12 个 token，加上 α = 0.3、σ = 2.0 后停在 10 个。这只是一组已发表系数，没有搜索。三项都可以进入以后的宏观比较，但现在还没有量化器和下游分数，所以不在这一层选边。

本层不选择数据集，也不启动训练。

此前的介观：

介观：格点与序列的接口（底稿、邻接、覆盖形状、扫描、停止、逐格解码和侧信息）。它决定宏观问题测到的到底是合并，还是位置编码、重叠约束和有损量化。

文献接口至少包括这些可分开的部件。底稿是灰度值、颜色量化，还是 VQ 码本索引。邻接是拉平后的前后符号，还是网格上的水平与垂直。一个合并符号覆盖的格子是矩形 patch，还是可以不凸。序列顺序是锚点的扫描顺序。下游还可能收到下一块坐标、覆盖区域的位置编码，以及生成时对越界和重叠的禁止。可逆性要写明还原的是量化格点，还是重采样后的像素。

仓库现状的接口更窄。输入是带 batch 维的 CPU 整数张量，形状沿整除链 patch，重建顺序就是 token 顺序，不另附坐标。`encode` 不改词表。这个接口足够做合成往返，不够代表 Elsner 等人的生成接口，也不够代表 Zhang 等人放进语言模型的 ID 序列。

这份最小接口写在架构设计的介观一节。2026-11-09 的四个对照都在它里面，每次只改一个部件。仓库 patch 链的往返仍然不是二维 BPE 的复现。

会改变这一层判断的观察有两条。同一个合并规则，只加上或去掉下一块位置，下游差异就大于更换合并规则。或者命题 2 的按行合并，与算法里的任意形状，在同一网格上得到不同划分。出现任一条，宏观比较都要把位置和形状写成因素。
