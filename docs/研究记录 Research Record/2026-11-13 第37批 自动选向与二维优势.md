# 第 37 批自动选向与二维优势

## 总览

1. **混合长条上，自动选向比固定扫描省文件吗？** **是。** 测试只看输入格子，32 张均选对方向。主对照的 Huffman 文件小 75%–77%，追回固定扫描相对二维约 93%–94% 的字节差。紧凑块全选按列，token 数与固定按列相同。
2. **计入词表和码表后，自动选向的 Huffman 文件比二维小吗？** **否。** 混合长条的两档都是二维更小。总规则数相同、各用原打包位宽的 zlib 文件，两档都是自动选向更小。
3. **文件都能逐格还原吗？** **是。** 两种规则计法下，16 个新文件与 16 个复用对照均通过。 [运行记录](<../运行记录 Run Record/2026-11-13 第37批 自动选向完整文件对照.md>)

## 分项证据

### 固定扫描承担了混合长条的大部分代价

- **依据。** 验证集选出相邻格分数阈值 9,024，测试只按输入格子计算分数。混合长条两档的 Huffman 文件从 67,307、65,999 字节降至 16,683、15,393 字节。紧凑块全选按列，增加的 116–840 字节来自第二套词表、方向标记及适用的码表。 [阈值、逐图选择和字节](<../运行记录 Run Record/2026-11-13 第37批 自动选向完整文件对照.md>)
- **适用范围。** 128×128 四级合成格子，每种布局测试 32 张。长条横竖平衡，图内长条方向一致。固定扫描按第 36 批的验证集预先选定。
- **待验证。** 阈值 9,024 在验证集仅比次选 92 省 24 字节。现有长条方向强，换成同图多方向、倾斜或弯曲的结构后，选向及文件收益还需复测。

### Huffman 下的二维优势主要来自数据块

- **依据。** 混合长条 64 条下，自动选向少留 token，但每个 token 平均要用 6.69 比特，二维只需 4.80 比特。3,062 字节的文件差有 3,006 字节来自数据块，方向位只占 4 字节。把总规则数对齐后，二维在混合长条两档仍分别小 4,687、4,177 字节。 [字节分项与总规则数对照](<../运行记录 Run Record/2026-11-13 第37批 自动选向完整文件对照.md>)
- **适用范围。** 规范 Huffman，码表来自冻结验证集，逐图分块，完整文件计入所有词表、码表、头部和填充。
- **待验证。** 改用另一种 token 编码或在真实输入上分配行列规则预算时，二维的数据块优势能保留多少。

### zlib 的排序对打包宽度敏感

- **依据。** 总规则数为 256 时，长条自动选向写出 10,563 字节，二维为 14,290 字节。保留自动选向的原 token 和方向，只把定宽打包从 8 位改为 9 位，长条 zlib 数据块就多 7,214 字节，超过全部文件优势。同一对照下，紧凑块原本也由自动选向更小，改宽后优势消失。16 个自适应文件均以独立进程从文件逐格还原，对照文件也从原件重解码。 [打包宽度检查与逐格验收](<../运行记录 Run Record/2026-11-13 第37批 自动选向完整文件对照.md>)
- **适用范围。** 现有定宽打包、逐图 zlib 与两档词表规模。总规则数对照保持主实验的阈值，行列各得一半规则。
- **待验证。** 在相同打包宽度下对比不同切词和零规则基线，以及非方形、带孔域和更高维输入的完整文件。
