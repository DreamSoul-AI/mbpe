# 多维 BPE 阶段结论

2026-11-13 · 证据汇总至第 32 批

## 总览

1. **二维 BPE 在已测的原尺寸 MNIST 上比最强一维切得更短吗？** **否。** 放大后的四级格子上，二维胜过按行。四级与 Hilbert 尚未比较。112×112 二值上，Hilbert 三档都领先。
2. **到第 32 批，二维少留 token 是否已经验证为更小的完整文件？** **尚未验证。** 当时 BPE 只做了比特估算。合成矩形和圆盘上还出现过二维 token 更少、估算总比特更高的例子。
3. **第 32 批的输入整数格子都还原了吗？** **是。** 30,000 次逐图检查通过。完整二进制文件的独立解码从第 33 批开始验证。

## 分项证据

下文的二维 BPE 指项目的频次版候选。一维 BPE 的扫描顺序包括按行、按列、蛇形和 Hilbert，具体比较对象见各条结论。长度是 token 数，估算比特和实际文件大小分别注明。

### 自然图像与原尺寸 MNIST 上，强一维基线更短

- **依据。** 第 29 批的 32×32 原像素上，CIFAR-10 单通道以蛇形 token 最少，SVHN 和 CelebA 灰度样本以 Hilbert 最少。第 30 批自然图像掩码上，Hilbert 在所有已测组合中短于二维。第 31 批原尺寸 28×28 MNIST 上，二维在两种掩码、两档学习规模和三个预算下，token 和估算比特均高于当时最强的一维。1024 条时按行的 token 最少。 [第 29 批](<../运行记录 Run Record/2026-11-11 第29批一维基线与二维收益.md>) · [第 30 批](<../运行记录 Run Record/2026-11-11 第30批掩码上的一维与二维.md>) · [第 31 批](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>)
- **适用范围。** 已测的小尺寸整数像素、阈值掩码和规则预算。
- **待验证。** 原生较大、重复二维图案更多的输入能否改变排序。

### 放大四级 MNIST 上，二维胜过按行

- **依据。** 56×56、84×84、112×112 三个尺度下，二维在 64、256、1024 条预算上都比按行少 token 和估算比特。112×112、1024 条时，二维与按行分别为 46,753 和 123,244 个 token，估算分别为 0.03673 和 0.09035 比特/格。二维数字已计入加宽后的位移。 [第 31 批 P24](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>) · [第 32 批四级结果](<../运行记录 Run Record/2026-11-13 第32批MNIST放大尺度对照.md>)
- **适用范围。** 同一批 MNIST 最近邻放大后得到的四级格子，比较对象为按行一维。
- **待验证。** 放大四级还未对比 Hilbert，实际完整文件的大小排序也未验证。

### 放大二值 MNIST 上，领先顺序随尺度和规则预算变化

- **依据。** 56×56 的二维在 64 和 256 条时胜按行，1024 条时按行略优。84×84 的二维三档都胜 Hilbert，只有 64 条时也胜按行。112×112 的三档都是 Hilbert 第一、二维第二、按行第三。以 1024 条为例，三者分别为 26,138、32,174、43,933 个 token。 [第 31 批 P24](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>) · [第 32 批二值对照](<../运行记录 Run Record/2026-11-13 第32批MNIST放大尺度对照.md>)
- **适用范围。** 同一批最近邻放大的 MNIST 二值格子。56×56 只比较了按行和二维。
- **待验证。** 56×56 的 Hilbert 排序、原生大图的排序，以及结果对放大周期和 Hilbert 路径对齐的敏感性。

### token 优势需要用完整文件确认

- **依据。** 第 30 批四级合成矩形与圆盘在 1024 条时，二维比 Hilbert 少 970 个 token，估算总比特却更高（0.3759 对 0.3558 比特/格）。第 32 批在部分放大四级设置下，二维估算低于打包 zlib 的实测值，例如 112×112、1024 条时为 0.03673 对 0.05372 比特/格。 [第 30 批 P20](<../运行记录 Run Record/2026-11-11 第30批掩码上的一维与二维.md>) · [第 32 批计费及 zlib 对照](<../运行记录 Run Record/2026-11-13 第32批MNIST放大尺度对照.md>)
- **适用范围。** BPE 数字是经验熵加估算的词表及边信息。zlib 数字是实际打包输出。
- **待验证。** 各方法能否仅凭落盘文件逐格还原，以及计入实际编码、完整词表和文件头后，二维能否胜过强一维与打包 zlib。

### 紧凑块占比和短程相关性只能提供解释线索

- **依据。** 原尺寸 MNIST 有一档紧凑块约占字典的 76%，实际替换却约占 20%。放大后，56×56 和 112×112 的紧凑块约占实际替换的一半，84×84 约占 24%–27%，四级二维仍胜按行。另在 CIFAR 掩码留出统计中，蛇形在只看前一格时更可预测，Hilbert 在看前四格时更可预测。 [第 31 批 P23](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>) · [第 32 批形状占比](<../运行记录 Run Record/2026-11-13 第32批MNIST放大尺度对照.md>) · [四种展平的顺序统计](<../运行记录 Run Record/2026-11-12 掩码上四种一维展平的顺序统计.md>)
- **适用范围。** 紧凑块比例按已发生的替换次数计算。短程可预测性来自 CIFAR 掩码的条件熵统计。
- **待验证。** 在固定尺寸和值频后，改变图案形状是否会改变压缩排序。现有统计还无法解释 Hilbert 为何在 112×112 二值上领先。

### 逐格还原已在指定输入和实现上通过

- **依据。** 第 32 批新增配置共 30,000 次逐图还原检查，失败为零。候选此前也通过了 29,160 次有限小域的序列化往返。作为边界案例，Elsner 的原生还原在第 31 批的二值 MNIST、64 条规则、100 张测试图上有 84 张失败。Zhang 后续公开快照在固定 CIFAR 输入上出现首轮方向碰撞，另存方向后本批输入可逐格恢复。 [第 32 批运行记录](<../运行记录 Run Record/2026-11-13 第32批MNIST放大尺度对照.md>) · [候选往返检查](<../运行记录 Run Record/2026-11-11 碰撞复现与无损候选.md>) · [第 31 批官方对照](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>) · [公开快照碰撞复现](<../运行记录 Run Record/2026-11-11 碰撞复现与同输入对比.md>)
- **适用范围。** 候选还原的是输入的整数格子，官方问题对应各自的固定代码版本和数据。
- **待验证。** 候选完整二进制文件的独立解码。对底层替换实现的普遍正确性仍依赖划分不变量和后续验证。 [无损条件与推导](<2026-11-11 无损合同形式化与碰撞条件.md>)
