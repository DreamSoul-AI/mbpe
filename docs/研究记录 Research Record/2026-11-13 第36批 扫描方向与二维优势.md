# 第 36 批扫描方向与二维优势

## 总览

1. **扫描方向能解释长条上大部分 token 差距吗？** **是。** 横条按行、竖条按列后，256 条下二维相对 Hilbert 的 token 优势缩小了 94%–99%。64 条下两种方向都由一维留下更少 token。
2. **已知长条方向后，二维的 Huffman 文件仍更小吗？** **是。** 两个方向、两档预算都更小。zlib 在 64 条时两组都是一维更小，256 条时竖条是二维更小，横条的区间跨零。
3. **本批验证了未知方向下的自动选向吗？** **否。** 本批按已知方向分组，1,536 次新文件独立解码全部通过。第 37 批补做了自动选向。 [第 37 批结论](<2026-11-13 第37批 自动选向与二维优势.md>)

## 分项证据

### 方向对齐解释了长条上大部分 token 差距

- **依据。** 验证集两档均为横条选按行、竖条选按列。256 条时，二维相对 Hilbert 在两组分别少 32,522、31,860 个 token。换成所选扫描后，差距收窄为 419、1,812 个。64 条时，二维分别多 1,814、704 个。配对区间均支持这些方向。 [对齐扫描与 token 差](<../运行记录 Run Record/2026-11-13 第36批 等预算扫描顺序对照.md>)
- **适用范围。** 128×128 四级长条格子，横竖各 16 张测试图，学习使用两种方向的混合集。
- **待验证。** 倾斜、弯曲或一张图内同时存在多个方向时，对齐扫描能解释多少差距。

### token 排名和完整文件排名取决于编码后端

- **依据。** 64 条时，方向对齐的一维虽少留 token，二维平均 Huffman 码长更短，横竖文件仍分别少 855、1,895 字节。改用 zlib 后，一维分别少 2,014、853 字节。256 条时，横条的二维 zlib 文件多 43 字节，配对区间 [−85, 170]。紧凑块 256 条下，二维 Huffman 为 10,472 字节，验证集选出的按列为 30,694 字节。 [完整文件、码长与区间](<../运行记录 Run Record/2026-11-13 第36批 等预算扫描顺序对照.md>)
- **适用范围。** 当前两种逐图编码后端、等规则预算及含词表、位移与码表的文件口径。
- **待验证。** 按验证集选定的逐图方向策略，计入方向标记和词表后能否缩小混合方向集上的差距。

### 现有文件能独立恢复所测格子

- **依据。** 新写的 72 个文件全部逐格恢复，同配置的两种后端读回一致的规则和 token。原二维、Hilbert 文件及输入清单也已对回第 35 批哈希。 [逐格验收](<../运行记录 Run Record/2026-11-13 第36批 等预算扫描顺序对照.md>)
- **适用范围。** 稠密四级方格、固定词表和现有研究文件格式。
- **待验证。** 原生离散格子上的文件排序，以及非方形、带孔域和更高维度的完整文件表示。
