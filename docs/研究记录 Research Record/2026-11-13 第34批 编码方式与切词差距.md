# 第 34 批编码方式与切词差距

## 总览

1. **换成 Huffman 后，二维能比 Hilbert 写出更小的文件吗？** **否。** 冻结切词后，两者差距缩小约 5%–17%，三组仍是 Hilbert 更小。
2. **等预算时，Huffman 数据块差距主要来自 token 数吗？** **是。** 两边平均码长接近，二维留下的 token 更多。
3. **这些排序已在独立的原生二值或标签格子上复核了吗？** **尚未验证。** 本批复用第 33 批的 CelebA 裁块掩码。

## 分项证据

### 换编码后，二维与 Hilbert 的差距仍在

- **依据。** 四级 256 条对 256 条的文件差由 6,980 降到 6,658 字节。二值的验证集选定配置由 7,697 降到 6,390 字节，二值等预算由 6,711 降到 5,723 字节。三组差距均未达到预设的减半或变号。272 次逐图解码全部通过。 [完整字节与配对区间](<../运行记录 Run Record/2026-11-13 第34批 固定切词编码对照.md>)
- **适用范围。** 同一组未经缩放的 CelebA 裁块、固定词表和切词，比较定宽打包加 zlib 与用验证集构造的零阶 Huffman。
- **待验证。** 其他数据与考虑 token 邻接关系的编码方式下，差距是否保持。

### 等预算的差距主要来自 token 数

- **依据。** 四级 256 条时，二维和 Hilbert 分别留下 46,210 和 40,092 个 token，平均为 7.56 和 7.48 比特/token。二值 64 条时，两边分别留下 29,707 和 21,872 个 token，平均为 5.76 和 5.78 比特/token。按 Hilbert 的平均码长换算，token 数差足以解释四级约 93% 的有效负载比特差，以及二值等预算的全部有效负载差，后者有少量码长抵消。 [token 与码长分解](<../运行记录 Run Record/2026-11-13 第34批 固定切词编码对照.md>)
- **适用范围。** 两个等预算、逐图补齐、单表 Huffman 对照。
- **待验证。** 哪些二维规则或图案导致 token 差距，以及固定取值分布和尺度后，紧凑块的复用能否扭转它。

### Hilbert 256 加 Huffman 小于上批的零规则基线

- **依据。** Hilbert 256 加 Huffman 在四级和二值上分别为 38,630 和 15,595 字节，低于上批 Hilbert 零规则加 zlib 的 40,416 和 17,524 字节。 [基线字节](<../运行记录 Run Record/2026-11-13 第34批 固定切词编码对照.md>)
- **适用范围。** 这里比较的是两套完整流程，同时变化了合并规则与后端。选择来自已冻结的第 33 批验证配置。
- **待验证。** 在独立数据和同一后端下单独量出合并规则的贡献。CelebA 的身份独立性未核实。
