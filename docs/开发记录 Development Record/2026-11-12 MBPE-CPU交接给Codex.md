## 怎么比、怎样算赢

主要看两件事：剩余 token 数相对原始格子数的比例（越小越好），以及合计比特（token 加上这一组测试图只摊一次的字典，再加上边信息，单位是比特/格）。不要把 token 变少直接说成文件变小。需要时对比 zlib 等级 9，分两种存法：每格一个字节再压，以及按位打包后再压（二值 8 格一字节，四级 4 格一字节）。

合计比特的算法必须与第 30、31 批同一套口径，不要另起一套。一维字典是字母表位图加上每条规则两个符号号；每张图另加 16 位长度和一个域标志。二维每条规则再加每个维度 6 位位移，每张图的形状是每个维度 8 位（二维共 16 位）再加一个域标志。符号号宽度按“字母表大小加规则数”计算。一阶估计如果要写，只是 token 流的条件熵下界，不是已经做成的编码器，不要把它当成压缩结果。

二维算赢，必须在 token 数和合计比特上都短过当时最好的一维。只短一边不算赢。必须逐张检查还原：二维是字典和 packet 做往返后逐格比对，一维是按规则展开后和原序列逐项比对。还原失败要写清楚，不能略过。

掩码定义与第 31 批相同。bin128：像素大于等于 128 为 1，否则 0。4level：像素整除 64，得到 0 到 3。MNIST 学习图用种子 20261112 从训练集 60000 张里不放回抽 1000 张，300 张是这 1000 张的前缀；测试是测试集文件顺序的前 1000 张。边长不是 2 的幂时，Hilbert 用更大的 2 的幂曲线再裁回图内，并检查落在图内的点不重不漏。

普通一维 BPE 与第 29–31 批相同：只合并相邻一对，次数小于 2 就停，并列时取字典序较小的一对，从左到右不重叠替换。预算 64、256、1024 是同一次学习的前缀。

## 已经得出的结论（直接当事实用）

实验记录现位于 `docs/运行记录 Run Record/`。先读[第 29 批](<../运行记录 Run Record/2026-11-11 第29批一维基线与二维收益.md>)、[第 30 批](<../运行记录 Run Record/2026-11-11 第30批掩码上的一维与二维.md>)和[第 31 批](<../运行记录 Run Record/2026-11-12 第31批真实二值数据MNIST上的一维与二维.md>)正文。

1. 原始 8 位自然图像上，二维没有好处。CIFAR-10 上最短的是一维蛇形，二维几乎全在学横向一对，等于在做按行一维；SVHN 和 CelebA 上最短的是一维 Hilbert，二维没有短过它。原因是原始像素里值完全相等的邻居很少，精确匹配 BPE 吃不到“相近但不相同”的冗余。合计比特最好也只是略差于 zlib，不是差很多，例如 CIFAR 绿通道蛇形 1024 条约 7.499 bpp，对 zlib 约 7.452。相对文本，原始像素上 BPE 的增益小很多。详见 `2026-11-11 第29批一维基线与二维收益.md`。

2. 把自然图像做成小字母表阈值掩码之后，只读的上下文统计仍显示二维结构（比最好一维少大约四分之一到三分之一比特），但第 30 批真正跑 BPE 时，二维仍然没有短过 Hilbert。例如 CIFAR 红通道 bin128、1000 张、64 条：Hilbert 剩 8.36%，二维 10.68%。只有 64×64 合成矩形/圆盘上，二维 token 在高预算可以更短，合计比特仍常是 Hilbert 更省，因为二维要存位移。官方 Elsner 在这些掩码上 64 条更长，而且还原大面积失败。详见 `2026-11-11 第30批掩码上的一维与二维.md`。

3. 真实 28×28 MNIST（本机已有，不是下载的新数据）上，二维仍然没有赢。两个掩码、300 或 1000 张学习、64/256/1024 条规则，token 和合计比特都没有短过当时最好的一维。学 1000 张、1024 条时最短的是按行，不是 Hilbert：bin128 按行 2.6818%（21025），Hilbert 3.2554%，二维 3.8813%（30429），二维比按行大约多 45% token。bin128 按位打包 zlib 是 0.2836 比特/格，最好的 BPE 是按行 0.2953，仍略高。4level 按位打包 zlib 是 0.5031，按行从 256 条起可以低于它，最好 0.4884；二维最低 0.5654，连按字节 zlib 0.5445 都没低于。我们的一维和二维都能还原。详见 `2026-11-12 第31批真实二值数据MNIST上的一维与二维.md`。

4. 官方 Elsner 在 MNIST bin128、64 条、100 张测试上，100 张里 84 张还原失败，token 也比 Hilbert 和我们的二维都长；8 条时还原是好的。不要去查官方代码。同一批里，字典在 64 条时就已经有大块，1024 条时紧凑块可以占规则的大多数，但测试时大约八成替换仍是长条，所以块熵里“方块更常整块同色”没有变成二维的压缩优势。

5. 把原图用最近邻放大到 56×56 以后，二维可以短过按行。4level 上三个预算的 token 和合计比特都更低，1024 条大约少 32%，合计也低于按位打包 zlib。bin128 上二维在 64 和 256 条两项领先，1024 条按行略短。这是放大后同色块变大，二维才用得上，不是原尺寸 MNIST 的结果。第 31 批 P24 只比了按行和二维，学习 300 张，测试 1000 张，没有再跑 Hilbert。不要把这条写成“真实高分辨率数据上的胜利”。
