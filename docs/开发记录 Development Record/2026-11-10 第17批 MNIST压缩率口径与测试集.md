# 2026-11-10 第17批 MNIST 压缩率口径与测试集

本批只查第 16 批的压缩率为什么对不上图 6。没有训练生成模型，没有改官方文件，没有改 `legacy/`，没有提交。

## 长度口径

对照的是 `third_party/MDBPE_TF/MDBPE/processor_python.ipynb` 的转写、合并和导出，以及论文正文里压缩率的定义、图 6 的说明和附录里的训练细节。

灰度是 256 级，不是二值化，也没有再量化成更少的档。笔记本先做 `ToTensor` 和 `Resize(28, 28)`，再乘 255 后取整。MNIST 原图本来就是 28×28。第一张训练图上，这条路径和原始 0–255 整数像素没有一个位置不同，最小值 0，最大值 255。这张图里实际出现 85 种灰度，是因为笔画没有用满 256 级。包装脚本里的 28×28 和 256 个额外 token 与论文这一行一致，所以包装设定没有改。

计数的长度是剩下的 token 个数。导出时每个不同的 unique id 写一条 `[class, x, y]`，x 和 y 是这条 token 的锚点，不另算成 token。没有分隔符，没有填充，也没有结束符。结束符只出现在后面的训练数据里：附录说一个 batch 会补到该 batch 里最长的那条，用的是 end-of-sequence。图 6 的压缩率用的是补齐之前的序列长度。本批没有跑那段训练代码。

初始长度是 28×28 = 784。压缩率是剩余长度除以原长。正文写明：压缩率 50% 指序列长度变成原来的一半，并且量在没见过的测试集上。因此图 6 的 54.23% 是还剩大约 425 个 token，不是被删掉 54.23%。把 54.23 理解成删掉的比例，会得到 45.77%，仍然不是第 16 批的 18.58%。

C++ 的 `write_token_sequences` 也是每个 id 写一次 class、x、y。本机没有编译器，这段只读了源码，没有跑。若把我们测到的长度乘以 3，全量测试集大约是原长的 55.57%，和 54.23% 接近，但论文和两份官方写出代码都把一条 `[class, x, y]` 算作一个 token。本批不采用这个读法。

## 规则套到测试集

规则用第 16 批已经学好的 256 条，文件是 `results/2026-11-10-elsner-mnist-bpe-50/rules.dat`，顺序没有改。第一条是 `[0, 0, 0, -1]`，最后一条是 `[311, 252, 0, -2]`。新 token 从 256 起，按学习顺序每次加 1，和笔记本在见到 0–255 之后的编号一致。

没有把学习子集加到每类 200 张。第 16 批每类 50 张、共 500 张的学习，在第一个 codeword 之后的估计就超过一小时。每类 200 张大约是四倍图片，会更久。按本批的时限保持每类 50 张。套用已经学好的规则很快，所以测试集从每类 100 张加到了全部 10000 张。

套用脚本是 `src/elsner_apply_rules.py` 和 `src/elsner_mnist_apply.py`。替换顺序按笔记本：先下邻居，再右邻居；同一轮里已经合并过的 unique id 跳过。先拿第 16 批保存的 3 张最终网格核对，unique id 和 class 都一致。再在原来的 500 张上重算，平均长度正好还是 145.672。

| 项 | 训练子集自测 | 测试集每类 100 张 | 全量测试集 | 论文图 6 |
| --- | --- | --- | --- | --- |
| 图片 | 500 | 1000 | 10000 | 没见过的测试集 |
| 平均长度 | 145.672 | 143.590 | 145.225 | 约 425 |
| 最短 / 最长 | 36 / 217 | 48 / 225 | 36 / 233 | 图里没有 |
| 占原长 | 18.58% | 18.32% | 18.52% | 54.23% |

训练子集自测比 54.23% 低 35.65 个百分点。全量测试集低 35.71 个百分点。数字在 `results/2026-11-10-elsner-mnist-apply/summary.json`。全量测试集套用花了 166 秒。

套到测试集之后，比例几乎没变。所以这 256 条规则下，差距不是“量在训练集上还是测试集上”。

还可能的原因：

- 规则只在每类 50 张上学到。测试集上的长度说明这组规则本身就会压到大约 18.5%，不是因为拿训练图自测才这么短。全量训练集是否会学出另一组、压得没这么狠的规则，本批没有重学。
- 图 6 可能来自 C++ 那次统计。C++ 里偏移是邻居锚点减当前锚点，笔记本是当前锚点减邻居锚点；方向都是两个正交邻居。本批没有编译，不能用同一批图比较两边的长度。
- 灰度档数、784 的初始长度、以及“剩余长度 / 原长”这三件事，对不上 18.5% 和 54.23% 的差距。

## 无损还原

`tests/test_elsner_apply.py` 用笔记本的循环作对照。合并之后按每个 token 的足迹把原来的灰度涂回去，图像与原图一致，没有重叠，也没有空像素。第二条规则使用前一条产生的新 class id。在 `third_party/venv_mdbpe` 里跑了 4 个测试，0.023 秒，通过。另外，上面核对过的 3 张真实网格也能涂回原图。
