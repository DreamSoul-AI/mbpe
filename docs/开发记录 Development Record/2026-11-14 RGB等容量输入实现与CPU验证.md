# RGB 等容量输入实现与 CPU 验证

## 目标与实现

用户授权目标模式推进约 30 分钟，落实新研究计划 E1。新增 `studies/rgb_input_codec.py`，负责 uint8 左差分及还原、逐通道 BPE、计数头、9 位流与字节值 BF16 输入；新增 `studies/rgb_capacity_study.py`，负责独立清单、分阶段学习、验证、测试前封存、输入保存、独立解码及配对汇总。源码在冻结时复制到运行目录，后台执行使用该快照。核心包、官方源码和 legacy 未改。

当前合同为固定的一/三通道稠密 uint8 格子，实验对象是 32×32 RGB。共享二维词表只有一套 256 条规则，通道之间不合并。RGB 的 6 字节计数头随输入传递，token 连续做 9 位打包；capacity=2、3、192 的输出都为 192 维 BF16。解码端不接收未补齐字节长度。任意形状预测、未知整数和强一维接口尚未实现。

`.bf16` 保存真实输入位模式。独立进程使用共享模型、约定形状和保存输入恢复 RGB，与冻结清单的整图摘要核对；结果身份也必须与清单一致。每条记录的 4 字节外层长度仅用于容器分帧，张量形状本来已知，不传递额外 token 数或未补齐载荷长度。

## 验证与环境

新增六项回归覆盖 RGB、模 256 边界、尾部补齐、错误计数及覆盖、截断、非法类型/形状、隐藏维度和非整数字节，以及排除旧样本、内容去重、均衡抽样及不足时明确失败。六项通过。

首次完整回归 63 项中 4 项因沙箱重写 TEMP/TMP、`tempfile` 退回 C 盘后访问被拒而失败。用 python-environment 技能诊断，在测试进程内设置仓库 tmp 和 `tempfile.tempdir` 后重跑，63 项全部通过。没有修改系统或 Python 安装。最终日志在本机运行目录 `offline-tests.log`；首次失败不计为通过，不冒充支持版本或远端 CI 验收。

本机沿用 Python 3.13.9、NumPy 2.5.4，项目声明仍为 Python 3.10–3.12，固定依赖未升级。Idle、一个 CPU 核、库线程 1、worker 0。正式运行前，两套数据各用 10 张学习、10 张验证通过冒烟和独立解码，未查看测试结果。CIFAR 正式 raw/difference 学习约 54/129 秒，进程峰值约 5.10/5.49 GiB，低于本次 8 GiB 保护线。

## 受限环境下的临时目录核验

本次回归中，PowerShell 设置 TEMP/TMP 后，沙箱仍改写了 Python 子进程的环境，实际临时目录回到 C 盘并报权限错误。用测试进程内的 tempfile.gettempdir() 核对，改为在该进程内绑定仓库临时目录后，4 项环境错误消失，63 项测试全部通过。
