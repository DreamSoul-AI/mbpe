# 2026-11-08 编码解码合同

修复 `encode` 返回值与 `decode` 输入不一致，并补上会挡住往返的两处终止条件。历史实现保留在 `legacy/`，本轮只改 `src/mbpe` 的当前入口。

修复前，单样本 `encode` 返回 token 列表，批量返回列表的列表，`decode` 却读取 `state.joined`，另外还要求调用者另传 shape 和 dtype。用形状 `(1, 1, 4, 4)` 的 uint8 张量、合并阈值 0.5 训练后，返回值是 `['256', '257', '258', '259']`；把这份列表交给 `decode` 得到 `AttributeError: 'list' object has no attribute 'joined'`。把同一列表放进 `State.joined` 后，逐值重建成立，说明展开和 patch 重建本身能对上，断点在返回合同。

另外两处旧路径没有成功结果：相邻对为空时 `np.argmax` 抛出 `ValueError`，未训练且频次总数为 0 时频率计算抛出 `ZeroDivisionError`。不可整除形状 `(1, 1, 3, 4)` 会在 patch 内部出现 `IndexError`。`None` 会在读取 `dim` 时出现 `AttributeError`。

现在单样本和批量都返回 `TensorEncoding`。它带有每个样本的 token 序列、原始 shape 和 dtype，token 顺序就是重建顺序。`decode` 只接受这个对象。`encode` 和 `decode` 若改变词表长度或频次总数会直接失败。训练仍允许更新词表和频次。

空相邻对现在停止。推断时频次总数为 0 也停止，不把未学到的对写进词表。已有频次且相邻对非空时，仍用原来的 `np.argmax` 取第一个最大频率；当前最大对不在词表中就停止。重叠对仍从左向右合并，不复用已消耗的位置。这三项语义在修改前的回归里已经通过。

非法张量改为 `TypeError` 或 `ValueError`。最终展开若留下无法解析的码字或拼不满一个 patch，也改为 `ValueError`，不再静默丢掉尾部。`train` 使用同一套张量检查。`Reconstruct` 里打印内部尺寸的调试输出已去掉，数值不变；构造 Tokenizer 时仍会打印码字形状。

保存格式只做了评估，见架构设计。没有新增调度、持久化模块或执行命令。验证见 [2026-11-08 编码解码往返](<../运行记录 Run Record/2026-11-08 编码解码往返.md>)。
