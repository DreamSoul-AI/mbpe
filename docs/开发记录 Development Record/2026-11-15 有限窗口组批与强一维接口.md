## 检查和修正

定向组批合同检查覆盖稳定窗口、双射、相同长度阴性对照、W=16 不改变分配、真实字节数、序列化往返与失败路径。强一维检查覆盖四扫描、原像素/残差 BF16 还原及不良规则拒绝。

第一次一维学习检查暴露：既有 `learn_apply` 不接受空的测试映射，会在汇总时触发 `StopIteration`。新适配器改为传入命名空检查组 `{'audit': []}`，复用原算法，不修改旧实现；此后两项定向检查通过。首次失败输出保留于本会话工具回执，未运行数据学习前已修正。

完整离线回归 69 项通过，实际耗时 11.128 秒；见 `tmp/2026-11-15-autonomous/offline-tests.log`。解释器为现有研究环境 Python 3.13.9，库版本与资源回执见运行记录；不能代替项目支持环境 Python 3.11 的安装或远端 CI 验收。临时目录在 Python 进程内显式设定，避免沙箱覆盖子进程环境变量后写往系统临时区。

## 收尾后的范围校准

用户要求后续把各数据集联合考虑并控制 CPU 内存。两份计划已补跨数据集评估、共享词表与混合组批的变量区分，明确 MNIST/CIFAR-10/SVHN/CelebA 按实际可用来源纳入，逐源结果与加权总结果同时报告。新增 D8 为有界读取、缓存与过程内资源检查，尚未实现或启动大实验。

源码核对发现 ND 学习器保留每份学习样本状态和合并出现位置，因此不能把迭代读取直接当作流式学习。后续先限制学习集做内存冒烟，编码/评估按需读取；初始任务 RSS 预算约 2 GiB、系统可用内存保留 4 GiB，运行前再冻结实际设置。原 E4/E2 的分源实验结论及执行时长保持原义。

用户随后明确“跨数据集暂时不需要”，两份当前计划已撤回相应排期；保留单数据集内的内存控制需求。上述跨数据集提议未实现、未运行，当前转为汇总已有压缩率及 PNG/zlib 同输入证据。
