## 一、Zhang 公开版的碰撞到底是什么

### 范围

只针对公开 Being-VL-0.5 固定提交 `e92ce36e3b8bf3e438a54a36025ecea3f8ae9170` 里的 `beingvl/model/vbpe.py`。这不是已证实对应 2410.02155 旧论文的实现，论文附录 A.1 作者自己也讨论过 BPE 的额外信息损失。所以能说的是：**这个公开快照的输出不满足本项目“逐格无损”的合同**，不能说“推翻了论文”。

### 2×2 反例怎么起作用

- A = `[[1,2],[3,4]]`，B = `[[1,3],[2,4]]`。
- 官方类在这两张图上学到一条规则 `(1,2)→256`。A 里 1、2 是**横向**相邻，B 里 1、2 是**竖向**相邻，两个都算这对的出现。
- 第一轮二维替换后，实现把结果变成一维数组，只按锚点顺序输出新符号，**没有记下这次合并是横的还是竖的**。于是 A 和 B 都输出 `[256,3,4]`，形状也一样（2×2）。
- 给定词表、形状、序列，解码端不可能知道 256 该横着铺还是竖着铺，所以两张不同的图无法区分。这和外部解码器聪不聪明无关，是输出里信息本身不够。

大白话：**丢的是第一轮合并的方向位**。之后的轮次已经是一维了，新符号是新编号，可以唯一倒回第一轮的序列；问题只出在第一轮“每个新符号是横放还是竖放”。（记录里还说明了二维 L 分支实际不可达，所以第一轮每个新符号恰好吃两格。）

### 1000 张/通道的统计实际说明了什么

三个数要分开读，分母都是各通道 1000 张：

| 通道 | 1000张内自然图互撞 | 有“另一张不同合法格子同输出”的真实图 | 简单逆展开失败 |
| --- | --- | --- | --- |
| 红 | 0 | 119 | 84 |
| 绿 | 0 | 135 | 86 |
| 蓝 | 0 | 180 | 116 |

- **0 互撞**：这 1000 张真实图两两之间没有编成同一串。原因很直白：两张自然图要撞，需要除了某些合并方向以外其余像素全都一样，自然图几乎不可能。所以 0 不说明“实际上没问题”。
- **119/135/180**：对这张真实图，外部构造出一张别的 32×32、值在 0–255 的格子，并用官方类实际重编码证实输出一模一样。也就是说，单看输出，这张图**不能被唯一确定**。这些替代格子不一定在 1000 张里。它是下界经过完整方向枚举补全后的计数，在该固定实现、固定形状、基值 0–255 的前提下没有遗漏。
- **简单逆展开失败 84/86/116**：只是一个外部简单解码器（按默认方向铺）猜错的张数。猜对也不代表唯一：横放的原图能被猜对，但同一输出可能还对应一张竖放的图。所以不能把“失败数”当碰撞率，也不能把“成功数”当无损率。
- **两个外部修法都 1000/1000**：A 是拉平用一维 BPE（丢了几何，只能当参照）；B 是保留官方输出，额外附第一轮方向位（306/288/405 bit），token 序列和长度完全不变。B 说明问题确实只差方向信息，但它是外部包装，不是公开格式本身。附加方向位、按 9 bit/token 定长粗算，三通道成本约为原 uint8 的 109.32%/109.13%/108.82%，这还没算字典和头，说明“能恢复”不等于“压缩了”。

### 对通用多维 BPE 的启示

1. **几何信息必须进输出合同**。任何“把不同方向/位移的同一对值并成同一个符号”的做法，只要输出里不再带位移，就会出这种碰撞。规则键必须是 `(A, B, 完整位移δ)`，同一对值的横、竖、斜各是不同规则；或者至少把方向作为侧信息显式存下并计成本。
2. **形状必须完整导出**。Elsner 官方在 CelebA 两张图上失败（88/90），不是合并丢信息，而是导出形状时只存了一个轴的偏移；非凸形状可以伸到锚点左边，第二轴偏移不能省。外部按完整二维位移递归合成形状后 90/90。这和 Zhang 的碰撞是两类不同问题，但教训相同：**形状/位移要按全部维度存**。
3. **“自然样本没撞”不能当无损证据**。验收应该是格式层面的证明 + 小域穷举 + 跨形状往返，而不是看数据集里有没有两张图撞上。我们的候选正是按这个口径验收的。

## 三、无损 ND 候选：H1 通过，H2 为什么是负结果

### H1（无损合同）结论

跨秩 0/1/2/3/4/8、不同训练/测试边长、带孔域、零边长、空域、未见负数和大整数全部逐点恢复；2×2 Zhang 反例在候选里两个 packet 不同；小域穷举共 29160 次字典/packet JSON 往返全部恢复，每组内不同输入没有同 packet，并且确认用到了真实合并（288/729 和 4160/6561 个输入用过合并符号）；随机 600 个变形状输入也通过。CIFAR 三通道 100 张两种计分都 100/100。这一部分可以作为“正确的任意维无损表示”的工程基础。

### 两种计分其实只在“同值自配对”上不同

读 `src/lossless_nd_candidate.py` 的 `_realizable`：A≠B 时直接返回原频次；只有 A=B（同一个值和自己配对，如 `(251,251,横)`）时才按链最大匹配算，结果 ≤ 原频次。记录里的结构推导也说明了这一点：A≠B 时每个区域至多参与一个该规则候选。

所以“可替换数计分”的实际效果只有一个：**把同值自配对（平坦区域的游程）的分数往下压**，把名额让给不同值的配对（如 `(127,126,横)`）。

另外，频次版的“选中分数”比实际省下的多 83/90/74 个 token（10 张合计），就是自配对链被重复计数的部分；可替换数版两者恰好相等，与记录一致。

### 解释（证据能支持到的程度）

1. **主要问题是过拟合 10 张学习图，不是计分对错**。两版在测试上都只保住学习集省量的约 1/4（21%–28%）。64 条规则里 63–64 条都是两个原像素值直接配对，几乎没有形成层级符号；配对键是“精确的两个 8 bit 值 + 方向”，在 10 张图上数出来的高频对，很多只是这 10 张图恰好有的颜色。
2. **可替换数计分让学习集更短，是因为它更准确地做了“单步贪心”**，把被高估的自配对换成在学习集上真能省的不同值配对。学习集上只多省约 0.6–1.2 个 token/张。
3. **测试变长，是因为被换进来的不同值配对泛化更差**。频次版里自配对的保留率在三个通道都高于不同值配对（红 27.9% 对 25.0%，绿 31.8% 对 24.1%，蓝 26.1% 对 21.6%）。直观理由：平坦区域（天空、背景、饱和 0/255 附近）在很多图里都有，同一个值连成一片的游程在新图上更容易再出现；而“127 挨着 126”这类具体值对更依赖某张图的颜色。可替换数计分恰好压低了更能泛化的那一类。
4. **频次对自配对的“高估”在这里反倒像一个泛化先验**：游程越长，频次越高，而长游程正是新图里也多见的结构。所以“更准的学习集收益”不等于“更好的规则”。

限定：差距很小（测试 0.04–0.18 个百分点），只有 10 张学习图、一个预算、一个数据集，三个通道方向一致但没有方差估计。以上是对这一批的机制解释，不是对该计分的一般否定。

### 更好的下一次计分/设计尝试

核心想法：**选规则时要看它在新图上能不能省，而不是在学习图上能省多少**。具体候选（都只改选对得分，其他合同不动，保持无损）：

- **S1 跨图支持度**：得分 = 该规则在多少张学习图里出现（或每张图的省量取上限再求和，如 `Σ_img min(可替换数_img, c)`）。只在一两张图里大量出现的颜色对会被压低。最简单、最便宜。
- **S2 留出验证选规则**：学习图分成“提名”和“验证”两半，提名集出候选，按验证集上的实际可替换数排序或设门槛（验证省量 < 某值就不收）。这是最直接针对“学/测保留率只有 1/4”的做法。
- **S3 带成本的选规则（MDL 风格）**：每条规则有字典成本（两个子符号 + 位移的比特），只有预计在新数据上的省量超过成本才收，并允许提前停在小于预算的规则数。这同时回答“总字节是否压缩”的问题。
- **S4 混合**：自配对用频次（保留游程先验），不同值配对用跨图支持度。属于 S1 的变体，有了 S1 结果再决定要不要做。

不建议继续在“学习集单步收益更准”的方向上加工，本批证据说明它在 10 张图上会放大过拟合。

## 四、下一步 CPU 实验（按优先级，不重做已完成工作，不与第26批重复）

第26批在补 Elsner 绿/蓝 1000 张，最多 7 个进程。下面所有实验建议**等第26批结束后**再开，或最多单核 IDLE 进行；都只用已冻结在 `mbpe-20261111-round2/inputs/` 的整数输入和已有 CIFAR 压缩包，不下载、不用 GPU、不量化。

### P1 候选 vs Elsner 同输入、同预算（最该先做，几秒到一分钟）

现在候选只有 64 条规则的数字，不能和 Elsner 256 条比。用同 10 张学习图、**256 条规则**、同 100 张测试图跑候选频次版（红绿蓝）。目的：确认“完整几何 + 严格无损合同”的实现，在 token 数上相对 Elsner 官方（96.7060546875% / 96.515625% / 96.6162109375%）是持平、更好还是更差。若明显更差，要先查规则语义差异（候选按 `(A,B,δ)` 区分规则；Elsner 的并列、去重、方向语义需逐项对照），再谈改进。判据事先写死：差距在 ±0.1 个百分点内算持平。

### P2 学习样本量曲线（便宜，直接检验“过拟合”解释）

候选频次版，学习图 10 / 30 / 100 / 300 张（从 data_batch_1 按类固定顺序取），预算 64 和 256，测试仍是同 100 张。增量计数在 20 张、256 条上约 0.28 秒，这些规模都很快。预期：若第三节解释成立，测试比例随学习张数明显下降，学/测保留率上升。这也决定后续所有对比该用多少学习图（10 张显然太少）。

### P3 泛化导向计分 S1、S2（核心改进尝试）

在 P2 选定的学习规模上，对比 频次 / 可替换数 / S1 跨图支持度 / S2 留出验证，每种都测 100 张、三通道。事先判据：在同规则数下三通道测试比例都不高于频次版，且至少两个通道低 ≥0.05 个百分点才算正结果；否则如实记负结果，不调参挑样本。再用 3 个不同的固定学习子集重复一次，给出波动范围（现在完全没有方差）。

### P4 诚实的比特成本账（纯计算，可用已保存原件）

对已保存的候选 packet、Elsner 输出、Zhang 输出分别算：token 流的经验熵（零阶）× token 数 + 字典比特 + 位置/形状/方向侧信息，对比原始 8 bit/像素。也可以加上对原始字节的通用压缩（如 zlib）作为参照线。目的是把“token 变少”和“比特变少”分开写清楚，论文里必须有这张表。

### P5 Elsner 形状导出问题的最小复现（写作材料，很小）

用一个手工构造的非凸形状（含 `(1,-1)` 这类相对坐标）几格的合成输入，只调用未改的官方导出/还原，得到最小失败例；再用外部完整位移解码恢复。和 Zhang 2×2 反例并列，作为“现有实现的无损合同缺口”一节。只写成复现与说明，不改官方代码，不向上游发 issue（如需发，先问 Enmao）。

### P6 形式化写作（无需算力）

把候选的无损性写成正式命题：不交划分不变量 + 锚点为字典序最小点 + 字典向前引用 ⇒ `decode_D(encode_D(X)) = X`；再写 Zhang 碰撞的充要条件（首轮存在可横可竖放置的新符号且两种放置都与基值一致）。这两条加上 P5，是“通用任意形状 BPE 的无损合同”这个论文主线的骨架。

### P7 超出二维的真实数据（之后再做）

现在只有 CIFAR 二维（加一次 32×32×3 整体三轴试验，98.935546875%，10 张学 64 条）。论文要说“任意形状”，至少需要一种本机已有的三维或带孔数据。先查本机已有数据，不下载；没有就暂缓，并注意 Elsner 原文已做过 3D 体素，不能把“多一维”本身当贡献。

### 可选、需 Enmao 拍板：无损预测变换

对像素做可逆的差分（如减左邻、模 256）再做 BPE，不是量化，完全可逆，通常会让数值集中在 0 附近，配对重复率会高很多，可能是跨过 88.89% 门槛最现实的路。但它把“只做 BPE”的边界往外推了一步，所以列为可选，先问 Enmao 是否在范围内。

### 关于论文方向的判断

基于现有证据，比较站得住的贡献组合是：

1. 指出并复现现有公开实现的无损合同缺口（Zhang 方向丢失、Elsner 非凸形状单轴偏移），给出最小反例；
2. 一个对任意秩、任意边长、带孔域、未见整数都可证明无损的 ND BPE 合同与实现（H1 已过）；
3. 精确保持语义的增量计数引擎（已有约 100 倍于自己全扫描的工程信号，需和文献里的增量 BPE/Re-Pair 区分）；
4. 如果 P2/P3 有正结果：面向泛化的选规则方法。

“支持更多维度”和“由覆盖区域推导位置”Elsner 原文已有，不能单独作为贡献。
