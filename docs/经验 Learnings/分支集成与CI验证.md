# 分支集成与 CI 验证

本次 MBPE 阶段收尾时，成果直接推入 main，仓库尚未配置持续集成。随后补做分支审计，确认 weiwen 的提交已包含在 main，chenyue 留有一个独有提交。用户要求保留该独有工作，建立 development 并从其派生任务分支。

日常任务应从更新后的 development 建立任务分支，经 PR 合入 development，再把验收阶段经 PR 合入 main。清理分支前以最新远端引用做祖先关系检查，保存实际头提交和合并依据。分支显示落后或文件相似时，仍需确认提交已合入。明确保留的独有提交继续保留。

CI 在干净 runner 检出目标提交，按项目声明的 Python 和依赖安装，再运行已有验收入口。MBPE 的研究包装采用 Windows 进程优先级 API，因此本轮 CPU 回归选 Windows runner。合并检查的依据需要包含远端实际运行，依赖环境和本地测试结果各有对应范围。 [工作流](../../.github/workflows/cpu-tests.yml) · [项目约定](../../REPO.md)

给 workspace 的候选改进是，在研发模板的阶段收尾入口提示核对长期开发分支、任务 PR、合并检查和清理状态。配置 CI 时应从项目现有测试入口、依赖和平台约束推导最小工作流，再验证首次真实运行。项目可以按实际交付需求裁剪部署步骤。此项供 workspace 后续审阅。
